# 版本通知、绝对截止时间与验证码准备任务

同日后续 [ADR-0014](0014-single-captcha-worker.md) 已取代本文“临时线程只做预取、现场取图由主线程执行”的分工：所有生产预约验证码统一由一个按需工作线程处理；本文其他等待、查询、持久化及日志决定继续适用。 后续用户同时确认快抢列表快照由 0.75 秒放宽为 2 秒，明确查询失败仍禁用旧行；见[调整验收](../acceptance/2026-11-04-opening-snapshot-2s.md)。

2026-11-04 用户确认实施 P0/P1/P2。保留 [ADR-0012](0012-query-owners-and-mail-worker.md) 的两个查询所有者、邮件发送线程和主线程唯一任务写入者；调整等待机制，并将生产模式的开抢验证码预取交给一个临时准备任务。正常现场取图、认证和提交仍由主线程执行。

主循环采用 Condition 和递增通知版本，来源为列表、历史、邮件和验证码。主线程在消费结果前确认通知版本，等待时在同一条件锁下比较版本并循环核对条件，避免发布发生在消费与等待之间时丢失通知。锁内不执行网络、磁盘或候选计算。真实运行以单调时钟计算本轮等待的绝对截止时间；持久化时间、学校开放时间继续保持原有语义，离线可单独注入单调时钟。

停止优先处理，跨进程停止 Event 尚未直接连接到 Condition，继续保留最多 0.2 秒的等待检查粒度。服务端等待不会被业务通知缩短，但期间可处理停止、邮件和健康状态。缺快照时等待新版本或最近阶段/准备/读者重启截止时间，最多五秒重新检查；健康刷新和五分钟告警可以截短内部等待。阶段参数变化通知健康读者重新计算本次间隔，不重建读者，不作为立即刷新请求；对齐仍只作用于列表读者的一次等待。

待确认核对分开处理正向证据和缺席检查。提交后产生的可靠列表或历史快照可以提前确认；一次有效缺席检查后设定两秒单调截止时间，任何通知都不能提前推进下一次缺席计数，两路请求仍须在各次检查开始后发起。刷新票据合并、错误退避、共享等待、提交前同步持久化和串行提交保持。

验证码准备任务只允许一个在途工作，独占借出的主业务会话执行取图和 OCR，完成后归还会话并通知主线程。主线程继续消费两个读者的快照；准备结束前不认证、现场取图或提交，也不修改该客户端的请求预算。结果和错误回主线程处理，不由工作线程写任务或发送通知。认证失效后丢弃原会话的准备结果；超预算、过期和非法识别结果不用作提交证据。同一开抢仍最多预取一次，拒绝后沿用原现场取图次数。直接查询的离线适配器继续同步准备，以兼容构造会话和时间。

取图请求受剩余读取预算约束；本地 OCR 和线程调度不能硬中断。退出等待准备任务归还会话，再关闭会话和日志；不承诺在本地 OCR 卡住时强制取消线程。该取舍避免关闭仍在使用的 Session 或交错生成验证码，不承诺提高命中率。

私有事件和诊断日志复用经安全打开的文件句柄、逐行 flush、加锁并在退出时关闭，仍只在启动时轮转；先关闭日志再释放任务锁，避免 Windows 删除账号时碰到未关闭句柄。任务检查点仍同步 fsync 与原子替换。P2 的目标服务器隔离磁盘实测未触发五毫秒条件，因此不增加健康或日志写入线程。证据及未验收项见 [P0/P1/P2 验收](../acceptance/2026-11-04-event-preparation.md)。
