# 选听完成记录接口调查

日期：2026-10-16（Asia/Shanghai）。本文记录学校接口证据、用户选择的统计口径及验证边界。

## 结论与用户目标

学校“我的活动”接口能够返回打卡、违约、类别及讲座时间等信息。用户已明确接受：以学校记录中 `SFDK='1'`、`SFWY='0'`、活动未取消的系列讲座计入本脚本的已选听次数。该口径不代替学院最终考核认定；评价或反馈是否另有培养要求，没有得到接口证据证明。

用户已确认的目标见[需求 Q22](requirements.md)：至少选听 8 场，法律、艺术、心理健康各至少 1 场；只统计上述三类及“其他”系列讲座，不预约、不计入“SEU咖啡间”沙龙。由学校记录提供进度，不要求用户手工维护次数。已选听与未来有效预约覆盖计划后暂停新增，但继续核对；按上述口径选听达标才结束，取消或确认违约后补足。进度每次由学校响应计算，不新增持久化的个人活动明细。

## 统计约定与客户端边界

- [`Client.mine`](../seu_reserve/client.py)使用 `queryMyActivityList.do`，请求 `param='{}'`。列表检查核实数组、行类型和响应中已提供的 `total`、`totalSize`、`totalCount`；没有总数字段时仍无法证明全历史完整。
- [`progress`](../seu_reserve/model.py)按活动 ID 去重计算；类别优先读取 `JZXL_DISPLAY`，兼容 `HDLX_DISPLAY`，仅将四类系列讲座计入目标。相同活动 ID 的统计状态矛盾时停止本轮提交，不能按标题推断类别或身份。
- `SFDK`、`SFWY` 必须为已知值；违约或取消不计入完成和计划。未打卡且尚未结束的有效预约占用计划缺口；已经结束、既未打卡也未标记违约的记录暂无法区分登记延迟与缺席，因此暂停新增并继续核对，不立即补约。
- 完成总量达到 8 且法律、艺术、心理健康各至少 1 才结束；已选听与待参加预约覆盖目标仅暂停新增。旧单场任务的 `done` 不代表新目标完成，旧任务迁移后重新查询学校记录。
- [`Lecture.read`](../seu_reserve/model.py)处理候选，完成统计单独处理我的活动记录；两类响应不能直接套用同一解析器。2026-10-18 已核对非空真实列表的 `JZMC`、`JZXL_DISPLAY`、预约时间窗及明确的线上线下标题标记，修正原构造字段不匹配造成的静默跳过；具体规则及验证边界见[数据契约](usage.md#当前业务数据契约与限制)。真实开放场景及完整预约流程仍待验收。

当前程序每次正常启动都会重新认证并读取学校进度，即使本地曾标记目标完成；规则见[需求 Q32](requirements.md)。任务检查点仅辅助本机恢复，损坏时保留原文件并停止，不能替代学校记录或证明预约成功。必要的当前列表筛选快照见[运行诊断](usage.md#运行诊断)，不保存完整个人历史。

## 限制与验证范围

- **培养认可**：本脚本统计用户已接受的学校打卡记录，不承诺学院最终认可；评价或预期反馈按钮不能代替认可字段。本科生课外研学、SRTP 学分系统的认定流程也不能套用到本项目的研究生讲座系统。
- **历史范围**：当前账号样本未发现分页信息和重复活动，已打卡筛选与默认列表一致；尚无独立总数或全历史契约，无法排除服务端截断或跨系统遗漏。
- **未来变化**：未知状态、缺失类别或相互矛盾的重复记录应阻止本轮新增预约，等待核实后再统计。
- **真实操作**：本次学校验证限于认证、只读查询及静态文件读取；未执行预约、取消、签到、评价或反馈提交。个人活动原始响应不进入仓库、日志或研究附件。
