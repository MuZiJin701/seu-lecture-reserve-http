# 2026-11-04 统一预约验证码工作线程

用户确认将所有预约验证码取图/OCR 交给一个工作线程后，在已有工作区改动上完成本轮调整；未部署、重启服务、提交或推送。承接 [P0/P1/P2 验收](2026-11-04-event-preparation.md)，规则与取舍见[使用指南](../usage.md#开抢与拥塞恢复)、[需求](../requirements.md#认证轮询与提交)及 [ADR-0014](../adr/0014-single-captcha-worker.md)。

## 实现

- 每账号首次需要验证码时启动一个 captcha-worker，后续预取、现场获取和判错重取全部复用它；工作线程负责单次取图、图片校验和 OCR，空闲等待指令，不周期取图或建立库存。
- 主线程独占派发和结果消费。最多一个在途任务或未消费结果，编号递增、记录认证代次；新取图使旧缓存失效，旧认证结果不得提交。工作线程不自行重试、提交或保存任务。
- 继续借用同一主业务会话，期间不认证、提交或复制该会话。两个已有独立读者继续查询；主线程等待结果时处理读者错误、可靠历史更新、阶段参数、共享等待、停止、邮件及健康状态。
- 返回后用已有可靠列表/历史快照重算目标进度、候选和冲突，快照不可靠、满额或存在冲突时放弃当前提交，不为复核新增学校查询。待确认、提交前同步保存及最多四次尝试保持。
- 预取保持原短预算和每场最多一次；现场任务保持普通十秒、开抢八秒。截止从派发计算，线程调度过晚不再取图，实际取图前再检查共享服务端等待；结果超过预算或图片收到后五秒未用时丢弃。五秒是本地保守限制，不代表学校承诺。
- 停止后不再派发，未开始任务可取消，已运行任务安全归还会话后退出；HTTP 有读取预算，OCR 和 Python 线程不能硬中断。`--check` 仍只读取图，直接查询离线适配器仍同步执行；生产 CLI/管理台均走默认后台模式。
- 无新增依赖、配置项或网页操作；配置样例只修改说明、实际值不变。中英文 README、需求、CLI/Web 指南及 ADR 已同步。

- 工作区与原暂存区 `git diff --check` 通过；211 个受影响文档本地文件链接通过；配置样例实际值与原索引保持。

新增及调整的回归覆盖：

- 工作线程空闲复用、单任务与未消费结果互斥、错误回主线程后仍可复用、关闭后拒绝派发。
- 预取超时回退、预取中读者继续工作、认证失效先归还会话，再取新验证码。
- 现场取图和 OCR 在同一工作线程，主线程独占提交/Task.save；取图期间满额或新增预约冲突时不提交，认证失效后丢弃原结果，提交只能用重新认证后的结果。
- 取图期间的 Retry-After 阻止提交；任务派发后、实际取图前才收到 Retry-After 时，不再发取图请求。
- 停止信号可被主线程处理，退出等待在途取图安全结束，之后无提交或残留验证码线程。
- 连续四次验证码被拒后仍按原规则冷却并处理下一候选，五次取图复用同一线程，编号递增。

旧构造读者/时间测试用立即执行的验证码适配器，避免虚拟时间在真实线程完成前直接退出；真实线程并发另由 app.run 回归覆盖。新增服务端等待测试观察检查点和任务结束，不能要求主线程在二十秒服务端退避尚未结束时立刻产生回收诊断。

## 交付边界

- 未部署或更新生产服务，未发送真实短信/邮件、未提交/取消预约；真实开抢、验证码校验成功率和长期运行仍未验收。
- 在途 OCR/底层本地调用不能硬中断，最终停止可能等待会话归还；增加线程不会消除现场取图耗时。
- 工作区开始时已有交叠的暂存/未暂存改动；本轮保留原索引，未自动暂存混合文件，保留既有工作。
