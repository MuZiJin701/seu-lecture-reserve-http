# 讲座预约需求

截至 2026-10-29 的当前有效规则。本文汇总已确认需求；文末实施记录保留历史变化，不覆盖正文的当前规则。实现和真实验收分别见[使用指南](usage.md#验收记录)，术语见 [GLOSSARY.md](../GLOSSARY.md)。

## 产品范围

- 单账号、单实例的 Python HTTPS 客户端，主要面向 Linux 服务器，兼容 Windows；认证和业务请求均校验证书。
- 目标固定为至少选听八场人文与科学素养系列讲座，其中法律、艺术、心理健康各至少一场；“SEU咖啡间”系列沙龙活动仍可按配置预约，但不计入目标；测试活动及购票公告不预约、不计数。依据学校记录统计，不要求手工维护次数，也不代替学院最终认定。
- 不区分年级，不提供三场目标、自定义次数、考核截止日、个人日历或跨机器协调。无候选时持续等待，直到实际达标或用户停止。
- 学校凭据、票据和完整个人活动记录留在仓库与日志之外；不自动取消预约、签到、评价或反馈。

## 目标统计与冲突

- 从学校“我的活动”读取进度，按活动 ID 去重；学校标记已打卡、未违约且未取消的四类系列讲座才可计为已选听。
- 按 2026-10-28 用户提供并确认的最新公告说明，沙龙既不计已选听，也不占待参加目标缺口，包括全部已有历史及已确认的本地占位；7 场正式讲座加 1 场沙龙不算达标。已完成任务启动后重新核对，不足时恢复补约；不删除学校记录或自动取消沙龙，已有有效沙龙预约及占位仍参与时间冲突保护。已知沙龙的打卡/违约结论不影响目标统计，已有预约状态、活动时间等冲突检查仍须可靠。
- 有效且尚未结束的待参加预约可占用目标缺口；已选听加待参加覆盖总量和必需类别后暂停新增，继续核对。只有已选听本身达标才结束，预约一场成功后继续执行。尚未结束的预约缺少打卡/违约字段时按“未参加、未违约”处理并计入待参加；记录结束后仍无法确定状态时才暂停。
- 取消或学校确认违约后补足；所选记录已经结束，但尚未登记打卡或违约时等待学校确认，不立即补约。
- 未知状态或类别、矛盾重复记录、已提供总数不一致时暂停新增。没有分页信息或总数不能证明全历史完整，证据见[接口调查](completion-records.md)。
- 旧版已确认占位缺少类别时，优先用本轮已有活动列表或历史补齐，不增加探测请求；仍不能确定类别时保留占位并暂停新增，不能漏计该预约。旧待确认记录缺少起止时间时保留待确认，不在无法建立时间占位时恢复提交。
- 新预约与学校全部有效预约检查冲突，区间重叠及首尾相接均算冲突；已有预约状态、时间或列表完整性不明时暂停提交。
- 不同 ID 的已有记录重叠时，只为本地计数选择互不冲突的记录：优先已打卡，再优先补齐缺少的必需类别，然后按结束时间较早、活动 ID 排序；每次选择后更新缺口并排除冲突项。不承诺全局最多场数，链式重叠可选择互不冲突的多场。
- 该选择不修改学校记录，不把未选记录自行标为违约；未选的有效预约仍用于拦截新预约冲突。

## 候选筛选

- 支持完整标题、类别、校区、线上线下开关和冲突筛选。标题列表非空时完整匹配，空列表不限制；指定标题仍受其他条件约束，同名活动按不同 ID 处理。
- 默认允许线上，线下只允许明确配置的校区；空校区列表不约线下。默认类别含心理、法律、艺术、其他及沙龙五类，名称见 [.env.example](../.env.example)；沙龙是否启用由类别配置控制，继续受标题、校区、线上线下、冲突及原有目标缺口预约策略约束。沙龙成功不减少正式讲座缺口，不设独立沙龙次数目标；正式讲座已选听加待参加覆盖目标时暂停全部新增，实际选听达标后任务结束。不增加日期范围、每日可用时段或时长筛选。
- 列表中类别非空、有效且明确不在启用类别内时提前排除，不要求其余讲座字段完整。类别缺失或异常、目标类别记录仍严格校验；此例外不适用于已有预约及目标统计。
- 非目标类别诊断保留可用标题和预约时间；标题缺失显示空字符串，无法解析的预约时间显示未知。其他正常记录按首个命中的筛选原因解释，不把未知结构当作空列表。
- 目标讲座须校验发布状态、预约时间窗和明确的授课方式；未开放时也校验。起止时间无法解析则跳过该候选，资格与名额以学校活动列表的已约人数／总人数判定及提交后按活动 ID 核对为准。
- 候选同 ID 且内容一致时只处理一次，矛盾候选暂停本轮提交。优先补齐必需类别并为其预留缺口，再按配置类别顺序、线上优先、开始时间较早排序，最后按 ID 固定顺序。
- 已有记录导致必须超过八场才能满足类别时，仅补必要类别。标题列表不表示优先级，筛选配置不排除历史记录的目标统计。

## 认证、轮询与提交

- 认证通过后才开始业务查询与提交。会话失效先尝试恢复或重新登录，需要人工操作时进入待认证状态；明确凭据错误或账号受限后停止自动登录并通知。
- 校园网访问讲座入口直接返回学校 CAS 登录页，且服务目标为 `ehall.seu.edu.cn` 时，先使用该服务完成统一身份认证，不主动进入 VPN；其他入口继续使用现有网关认证。CAS 自身要求的短信或其他挑战仍须处理，不承诺免短信。网络路径由用户管理，程序不修改 Clash、TUN、系统 DNS 或路由。
- 前台通过 SSH 输入 `send` 主动发送或重发短信，再输入六位验证码；不自动反复发短信，不设固定等待截止时间。过期后由用户重新获取，未知挑战说明原因并等待。
- 正常查询间隔十秒；预约开放时间前三十秒至开放后十分钟内以 0.10 秒为目标间隔顺序轮询，实际频率受请求耗时影响；开抢期可恢复的网络或响应异常仍按 0.25 秒间隔重试，过载及限流采用下述等待规则，发现候选后直接提交，不并发提交。开抢期优先保证活动列表轮询，历史记录查询失败不阻塞列表；开抢期默认每 5 秒用独立只读会话后台刷新“我的活动”（`SEU_HISTORY_BACKGROUND`，默认开启），主线程在下一次处理历史时及时采用更新的、10 秒内且无错误的快照并校验行格式，不等待旧缓存满 60 秒；启用后台刷新时主线程历史缓存同样最多保留 10 秒，过期、出错或格式非法时回退原同步查询，历史不可靠时暂停新增的规则不变；活动列表与历史刷新两个只读线程收到的 429／`Retry-After` 共用同一个“服务端要求等待”截止点，取验证码前、取图后提交前、同步回退及每次新请求前都会同时吸收两个线程的等待；历史线程在取图期间被限流时不会继续提交。仅开抢窗口且任务非待确认时运行、窗口结束即停止。该刷新替代原本开抢期 60 秒到期的同步刷新，增加历史查询频率以减少同步查询阻塞；关闭后回到 60 秒历史缓存＋主线程同步刷新。同时保留已知且未结束的开抢窗口，最新列表合法但暂时为空或缺少目标时仍按已知窗口维持快轮询，提交仍只依据最新有效列表。429/502/503/504 在读取响应体前按状态码与响应头判定；响应体按块读取，每次底层读取以剩余预算做 select 等待，gzip 解码与 chunked 分帧等内部连续读取同样受总预算约束，单次阻塞读取也以剩余预算作为 socket 超时；响应首部与响应体共用同一请求总预算，首部/连接/TLS 的阻塞读取按剩余预算收紧并在连接后校验，超预算同样按 `network_timeout` 中断；DNS 解析与纯 CPU 解析不受硬中断，6/8 秒是目标上限而非绝对保证。连接阶段超时视为请求尚未发出，可安全恢复扫描；读取超时或已发送但结果未知的提交仍按待确认处理。调度以学校服务器时间校准本机时钟偏差。429 严格按 `Retry-After` 等待，收到 429 或带等待值的过载响应后先等待，再发起历史探测或其他业务请求；两个后台只读线程与主线程共用这一等待截止点：每轮扫描先吸收两个线程的服务端等待、检查共同截止时间，再决定是否（重）启动后台线程，启动函数内部也会在未到期时直接停止返回；退避期间同时暂停活动列表与后台历史线程，冷却都钳到共同截止时间（取最长等待），恢复后各自按冷却重启；502/503/504 视为临时过载，按短退避恢复（无等待指令时约 1 秒起、上限 5 秒），持续失败仍按 5 秒上限重试，不改用长退避。异常采用 1、2、4、5 秒有界短退避，不使用 20–300 秒通用指数退避；重启恢复的旧等待值同样钳制到 5 秒（服务端有效等待值除外）；429 无可用 `Retry-After` 时同样短退避，学校有效限流要求优先；非法或不可持久化的等待值使用本地退避，不写入无限等待。启动后（认证前）加载 OCR 模型，避免首次提交才加载；取图与识别耗时写入本地诊断。开抢前约 2 秒（`SEU_PREWARM`，默认开启）用主会话查询一次“我的活动”，刷新历史缓存并保持验证码／提交连接热度；该查询替代稍后才会发生的历史刷新，不额外叠加长期请求；请求超时上界取 `min(1.5 秒, 距开抢剩余时间 − 0.1 秒)`，保证不会阻塞到开抢之后；距开抢剩余不足 0.4 秒时直接跳过预热、不发起请求；失败不阻塞提交，需要服务端等待时仍按原退避处理，其他失败只记录诊断。开抢前约 0.6 秒（`SEU_CAPTCHA_PREFETCH`，默认开启）取图并识别，候选出现后直接提交；只在开抢时刻前触发，开抢后不再预取；请求超时上界取 `min(0.6 秒, 距开抢剩余时间 − 0.03 秒)`；距开抢剩余不足 0.45 秒时跳过预取，预热结束后重新计算剩余时间再决定是否预取；超时或失败时回退为现场取图；预取结果超过 5 秒未用则丢弃并现场取图，被服务端判为验证码错误时回退现场取图重试（诊断 `captcha_prefetch_rejected`）。关闭预热或预取只回退对应准备；事件唤醒与健康快照合并没有单独开关。同一场开抢最多预热一次、最多预取一次：去重使用活动列表里稳定的学校开抢时间戳，不使用会随秒级校时抖动的本地换算时间；本地开抢估算取 `开抢时间戳 − 学校时钟偏移 − 余量`，余量取 `1.1 秒 + 该次列表快照年龄 + 该次列表请求耗时`，作为可能的最早开抢时间，不再用固定 2 秒上限兜底；余量超过 2 秒（`PREPARATION_MAX_UNCERTAINTY`）时跳过预热、验证码预取与可选对齐，并记录诊断 `preparation_skipped`（`reason=clock_uncertainty`，按开抢场次去重），候选仍可现场取图提交；估算按稳定学校开抢时间戳固定，重算只允许向更早移动，永远不会把准备截止点后移。预热、验证码预取与开抢对齐的目标取下一场尚未开放的场次；当前仍在快轮询窗口的旧场次不会挡住后续场次的准备。开抢窗口内使用独立会话（复制已登录 cookies）后台只读轮询活动列表，目标间隔 0.10 秒；主循环只消费 0.75 秒内的快照；快照过期但后台轮询正在请求时，先等待最多 0.3 秒的轮询完成事件，若后台仍在请求，再等待最多 6 秒复用该请求，仍不可用才同步回退（等待的是该过期快照之后的新版本，而不是上次已消费版本，两段等待合计上界约 6.3 秒），服务端等待与错误仍优先；后台轮询运行期间，开抢等待期内主循环等待后台轮询的完成事件（成功或失败都通知）而不是一次睡满整个间隔，且只对已消费快照版本之后的新轮询完成生效，旧通知不会导致空转，版本读取与清除之间完成的轮询也不会被漏掉；快照与版本号在同一把锁内读取，不会出现旧数据配新版本，不增加请求；服务端 429／`Retry-After`、过载等待与本地退避仍优先，事件不能绕过。开抢对齐是可选实验项（`SEU_POLLER_ALIGN`，默认关闭）：开启后主循环把按学校时钟校准的下一个开抢时刻交给后台轮询做一次性对齐，让某一次轮询落在开抢时刻附近，最多把该次等待延长到两倍轮询间隔且不增加请求；但学校时钟 `xtdqsj` 为秒级截断、后台快照带有年龄；校时校准后目标取最早的估算时间（通常早于真实开抢），尚未校时的首次对齐仍可能偏差，因此默认关闭，需在真实开抢中对比后再开启；后台线程不提交、不写状态、不发通知，出错即停止并由主线程按现有退避处理，至少冷却 5 秒后重启；后台收到的 429 或带等待值的过载响应，其等待同样约束主循环：等待期满前主循环不发起同步回退、验证码或提交等其他业务请求，无可用等待值时按短退避；仅开抢期启用，平时不增加请求。提交仍严格串行，不做并发提交。该频率与并发行为仍需实测，不能据此保证预约成功。
- 候选可用性按学校前端同款判定：发布状态、预约时间窗（以学校服务器时间为准）、已约人数与总人数（满员即跳过）；不再调用不可靠的预约前检查接口。提交结果以提交响应与按活动 ID 核对为准。
- OCR 输出只接受非空 ASCII 字母数字及现有长度限制。验证码明确错误或识别无效时，初次尝试外最多重新取图三次；仍失败则该场冷却五分钟，尝试其他候选。预取结果被判为验证码错误时只回退为现场取图，不额外增加尝试次数。
- 每次提交前持久化待确认活动 ID、首次待确认时间、连续核对次数及原活动的开始/结束时间。候选到提交之间只保留两次落盘：首次进入验证码阶段时的一次健康快照写入，以及把上述待确认记录与 `submitting` 阶段合并的一次原子保存；崩溃后仍先按活动 ID 查询、不盲目重提。响应成功也须按 ID 查询确认；超时或未知结果先多次核对原活动，期间不提交其他场次。连续 3 次有效查询仍未见原活动时，为每笔未确认预约保留独立时间占位并恢复扫描：所有占位共同参与时间冲突检查，其他候选与原活动重叠时跳过，每个原活动最多再提交 2 次；核对时优先查看后台只读轮询的内存快照：仅当快照时间不早于提交持久化时间且该活动显示已预约时，作为明确成功证据立即确认（`source=pending_snapshot`，诊断 `pending_snapshot_confirmed`）；快照中没有该活动不构成缺席证据，仍按两个来源核对。其他明确成功证据（“我的活动”记录、活动列表显示已预约、提交回复明确已预约）立即确认，先加入本地冲突集合再重算候选，不继续使用旧候选列表；已确认但尚未进入“我的活动”的占位继续保留到历史追上或占位到期。占位取原活动开始时间与建立占位后 600 秒的较早值，到期记录后释放。待确认核对同时查询“我的活动”和活动列表，任一明确成功即可确认，一个来源失败不阻止另一个；但遇到带 `Retry-After` 的限流或过载响应必须先按要求等待，不得先请求另一来源或增加核对次数，该次等待中断同样清零已保存的连续计数。两者都查不到仍不能当作失败。已确认但历史未同步的记录按活动 ID 合并进本地计划进度，避免超过目标继续预约。查询失败、记录矛盾或结构不完整时保持待确认并继续核对，该次核对不计入连续 3 次有效缺席次数、不推进自动解除，恢复后重新累计有效核对（失败时同步清零已保存的连续次数）；`--resolve-pending` 保留为人工兜底；不发送待确认通知。学校记录及时性与同一活动重复提交的防重能力均未验证，属于已知风险。
- 只有非零整数返回码且文案明确时，才可将提交响应认定为验证码错误或不可预约；缺失、空值、字符串或布尔码不能仅凭文案清除待确认状态。
- 首次登录的网关连接可按配置回退一次备用 IP，触发条件及限制见[网关回退](usage.md#网关回退)；不重放预约请求、不降低证书校验。

## 状态与恢复

- 同一状态目录通过文件锁限制一个实例；同账号在其他机器或浏览器版的实例须由用户停止。
- 正常启动始终认证并重查学校进度，即使本地任务已完成：仍达标就结束且不重复通知，不足则恢复扫描，再次达标时通知。
- `--new-task` 仅为重新核对已完成任务的兼容入口，不额外多约一场，不允许重置扫描或待确认任务。
- `--resolve-pending` 是待确认提交的人工兜底入口：停止运行中的实例后使用；只读查询“我的活动”，原场已出现则确认成功，未出现时必须由操作者显式输入确认短语才清除待确认与待确认占位；取消不改变状态；不发送提交请求。正常自动处理不依赖该命令。
- 重启保留待确认提交、待确认核对次数、待确认占位、冷却和退避；学校时间尚未校准时，保留并继续拦截已有冷却，不按本机时间判定到期；后续列表或慢路径复核缺少学校时间时沿用已知偏差。版本 1 单场任务自动迁移到版本 2 的目标任务。损坏状态、通知历史、非法恢复时间或账号不符时保留原文件并停止，不用新快照覆盖错误。
- 状态采用私有权限、原子替换和持久化写入；健康快照为观察用途，写入在等待边界按 phase 变化或约 1 秒节流刷新，退出前强制刷新；`authentication`、`captcha`、`submitting`、`confirming`、`manual_required`、`failed`、`done`、`waiting_for_attendance` 阶段进入前以及错误、邮件状态变化会立即写入 phase 与状态，因此普通等待下 `--status` 最多滞后约 1 秒，关键阶段进入时 phase 立即可见，但 `updated_at` 可能滞后到该请求结束；待确认前持久化、确认、占位与重试时间等关键状态仍同步落盘。错误退避时同时暂停活动列表与后台历史刷新线程，两者冷却都钳到共同服务端等待截止时间（取最长等待），恢复后各自按冷却重启。停止、SIGTERM 和 Ctrl+C 保留任务并释放锁，不取消预约。强制终止、断电无法保证退出通知。
- 从待确认恢复扫描时先建立替代占位，再清除待确认字段，确保中断退出保存的状态仍有保护。迁移和人工解除按活动 ID 保留其他预约的新旧格式占位，不整批清除。
- `--status` 离线显示本地状态及快照时效，不以 PID 文件或 `scanning` 判活；任务锁、阶段和成功查询时间共同提供运行证据，不能代替学校结果。
- `--check` 与扫描共用字段校验和筛选，展示逐场标题、首个原因及预约时间；不使用本地冷却，不创建或迁移任务，不提交、取消或发邮件。正常扫描的私有诊断快照跨重启保留；旧快照标注时间，不为诊断额外查询。
- 当前列表的必要筛选详情仅留在本地状态与终端，不进入事件日志或邮件，不保存完整个人历史。
- 私有诊断写入状态目录的 `diagnostics.jsonl`：扫描节奏、筛选变化、验证码、验证码预取、开抢前预热、提交、核对结果、快照确认、自动解除、待确认占位、预约关键步骤失败；提交记录含取图、OCR、连接建立耗时、候选数据年龄（`rows_data_age`）、提交前落盘耗时（`precommit_save_seconds`）及验证码来源（`prefetch`／`fresh`），扫描节奏记录活动列表来源（`poller` 快照或 `query` 同步查询）、快照年龄、列表请求耗时（`rows_fetch_seconds`）、数据年龄（`rows_data_age`）、主循环请求数与后台轮询次数；后台历史刷新命中和格式非法回退分别记录 `history_background_used`／`history_background_invalid`，余量过大跳过准备记录 `preparation_skipped`（`reason=clock_uncertainty`）；字段脱敏、只追加，不进入终端、邮件或事件日志；不自动轮转，由用户按磁盘情况清理。

## 邮件与告警

- 邮件是唯一主动通知渠道，可关闭；关闭后仍记录终端和本地事件。只读检查不校验邮件配置；独立 `--test-mail` 只发一封测试邮件，不访问学校或修改任务。
- `qq.com`、`163.com`、`126.com`、`gmail.com` 按域名精确匹配，大小写不敏感；仅需完整邮箱地址及授权码或应用专用密码，默认发给自己。非空显式主机、端口、发件人与收件人优先；其他域名需手动配置。
- 邮件字段全空或缺省时关闭，仅保留 `SMTP_PORT=465` 也关闭；部分配置不完整或无效则报错停止启动。使用校验证书的隐式 TLS，兼容无需认证的 TLS 中继；不增加明文、STARTTLS 或 OAuth。
- 只在重大问题尝试通知：需要人工认证、连续五分钟无法完成查询、连续五分钟无法完成验证码或提交请求（预约关键步骤失败）、可捕获异常退出、程序异常退出；预约成功通知受 `SEU_MAIL_SUCCESS` 控制，开启时每次经活动 ID 确认的预约成功发送一封，由后台线程发信、不阻塞扫描，关闭时不发；不发目标完成、待确认、恢复通知或日报。通知失败不改变预约结果，不触发重复预约。
- 同一未解决告警在发信前保存，跨重启只尝试一次；失败或结果不明不自动重发；问题解决后出现新问题可重新告警；恢复只记录，不再发信。关闭邮件不消费新的持久邮件配额。
- 持续查询失败从首次失败起计时，满五分钟后尝试通知一次；等待期间照常重试，告警不延后业务查询或退避；开抢窗口内延后到窗口结束再发送，期间恢复则不发送；查询恢复不发送恢复邮件。验证码或提交请求的连续失败单独计时（列表查询成功不清除），满五分钟通知一次；提交返回可判定结果、预约成功或不再有候选时视为恢复；同在开抢窗口内延后并去重，恢复不发送恢复邮件。
- 邮件使用中文说明和处理建议，包含最近核对的已选听、待参加、类别缺口、数据及查询时间、安全错误码和检查计划；未知进度不能写成零。不含讲座标题、学校凭据、验证码、票据或完整活动记录。
- 重大告警使用同步 SMTP，记录发送事件、实际耗时与固定错误分类，跨重启保留最近结果；成功通知复用 SMTP，但在后台守护线程发送，不更新重大告警的邮件历史字段。进程退出不等待成功通知线程，尚未完成的邮件可能中止；不自动补发，不输出异常原文、SMTP 响应或邮件地址。SMTP 接受和收件箱送达分别判断。

## 配置、入口与服务器运行

- 登录、筛选、状态目录及邮件统一用 `.env`；默认只加载当前目录文件，进程环境变量优先，显式配置文件不存在即报错，状态目录相对于配置文件。开抢提速的四个实验开关也放在 `.env`：`SEU_PREWARM`、`SEU_CAPTCHA_PREFETCH`、`SEU_HISTORY_BACKGROUND` 默认 `true`，`SEU_POLLER_ALIGN` 默认 `false`，均可分别关闭或开启；关闭预热或预取只回退对应准备，关闭后台历史刷新后回到 60 秒历史缓存＋主线程同步刷新，对齐由 `SEU_POLLER_ALIGN` 单独控制，事件唤醒与健康快照合并没有单独开关。只提交配置样例，不改写全局环境。
- 推荐 `uv run --locked main.py`，保留 `uv run main.py` 和 `seu-reserve` 入口；参数与退出码一致。启动、只读检查和测试邮件各展示一次维护者及项目链接，轮询不重复，状态与帮助保持简洁。
- Ubuntu 24.04 后台改用系统级 `systemd-run` 临时服务，名称 `seu-lecture-reserve-http`，以安装账号和项目工作目录运行；限制文件权限，保留追加日志和停止等待。SSH 断开继续，退出或服务器重启后手动启动，不自动重启、不自启。
- 服务不自动继承 SSH 临时环境。业务配置仍使用 `.env`；代理按需显式传入，不新增自动透传或 `.env` 代理字段，保留原环境优先级。
- 后台无交互终端而需要人工输入时，保留任务并退出；确认退出后前台处理；停止前台再启动后台会重新建立登录会话，不继承前台 Cookie，可能再次要求短信。预约前在最终运行进程中提前完成认证并保持运行。迁移旧 `nohup` 实例先核对命令、PID 和目录再停止，保留状态。使用文档提供检查、启动、查看、停止及恢复步骤。
- 双语 README 使用简洁步骤，全部配置先于首次运行；使用指南集中配置、排错和验收。全部文档核对并瘦身，历史截图和宣传素材不作为当前运行或验收证据。
