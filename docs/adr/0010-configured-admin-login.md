# 通过配置维护独立的管理员登录身份

2026-10-30 用户要求管理台增加管理员账号与密码登录，管理员账号由维护者通过配置单独添加或删除。第一轮已确认：全部管理员共享同一套学校账号并拥有相同操作权限，不提供注册或网页管理员管理；学校账号继续作为预约和选听进度的主体。

第一轮同时确认继续在可信局域网 / VPN 内以明文 HTTP 部署。新方案只取代 [ADR-0008](0008-trusted-environment-http-no-login.md) 的无登录子决策，保留其 HTTP 与文件权限取舍；[ADR-0001](0001-single-admin-multiple-school-accounts.md) 的单一操作者边界将调整为少数具有同等权限的管理员共同管理，不增加学校账号归属划分。

第二轮已确认管理员列表在服务器 `.env` 中以用户名和密码哈希维护，提供本地生成哈希命令，无管理员配置时拒绝启动。配置在启动前准备、仅启动时读取；增删与改密以重启管理服务生效，不引入热加载。管理员登录固定有效 12 小时、允许多端并存，退出只结束当前登录，管理服务重启使全部登录失效，预约任务继续按既有机制安全停止和恢复。该方案以少数可信操作者和简单配置维护为前提，接受配置修改需重启的成本，避免引入动态管理员管理与配置监听。

用户在两轮澄清及 Logo 补充后明确要求实施，方案据此接受。管理员登录及会话现已实现，见[控制台改版需求](../console-redesign.md)及[离线验收](../acceptance/2026-10-30-console-redesign.md)；真实部署及学校链路仍须分别验证。

后续用户要求直接在 `.env` 填写管理员账号和密码，免除手动生成哈希步骤。现允许同一列表混用普通密码与已有哈希，启动时把普通密码派生为内存哈希供登录校验，不改写配置文件；哈希命令保留为可选工具。该调整以部署便利为取舍，接受 `.env` 中明文管理员密码的本地存储风险，文件不得提交或分享；配置读取、会话与重启生效规则保持不变。
