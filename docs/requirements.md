# 当前业务规则

本文说明程序现在遵守的规则，供使用者和维护者核对。操作步骤见[使用指南](usage.md)，各时段的查询间隔见[预约查询策略](thread-query-strategy.md)，名词见[术语表](../GLOSSARY.md)。

## 产品范围

- 一个管理台可添加多个学校账号，各自认证、预约和保存进度。所有管理员共用账号列表，权限相同；没有注册或账号归属划分。
- 管理台使用管理员登录和明文 HTTP，只用于可信局域网或 VPN。学校请求使用校验证书的 HTTPS。
- 学校密码和 Cookie 在本地明文保存，网页不回显学校密码，凭据不进入日志或邮件。请保护配置和数据目录。
- 同一数据根只运行一个管理服务，同一账号状态只由一个进程写入。不同机器或数据目录不能协调重复预约，同一学校账号日常只保留一套实际预约任务。

## 目标统计与冲突

“有效已预约”需同时满足：学校显示已预约／预约成功，未撤回、取消或违约，且属于心理健康、法律、艺术、其他这四类正式讲座。按活动 ID 去重，不要求打卡；类别未知的记录不计数。

参考目标为至少八场，心理健康、法律、艺术各至少一场。它只用于展示，**达标后继续预约，直到手动停止**，也不代表学校认可学分。沙龙可按配置预约，但不计入目标；测试活动和购票公告不预约、不计数。

所有有效预约都参与冲突检查，包括沙龙和手动预约。时间重叠或首尾相接均算冲突。已有记录的状态、时间不明，或同一活动的记录互相矛盾时，先暂停新增。

## 候选筛选

- 按允许类别、完整标题、线上／线下开关、校区和时间冲突筛选。标题列表为空表示不限标题；校区列表为空表示不约线下场次。
- 网页管理的账号统一不限标题，并开启设备信任、我的活动预热、验证码预取和成功通知；收信邮箱为空时仍不发邮件。单账号 CLI 可单独配置这些选项。
- 候选按配置的类别顺序、线上优先、举办开始时间、活动 ID 排序；参考目标缺口不改变优先级。
- 用运行机器的时钟判断是否处于学校公布的预约时间窗，再结合学校发布状态和人数判断能否预约，不额外调用预约前检查接口。类别明确不允许时跳过；未知响应结构不能当作空列表，候选举办时间非法则跳过该场。

## 认证、轮询与提交

完成认证后才查询或提交。优先尝试校园直连，无法进入应用时按现有规则回退网关；明确密码错误时停止。短信由你主动发送并输入六位验证码，发送失败后按提示操作；只有服务器明确限流、要求等待或返回 502–504 时才限制重发。设备信任只尝试复用同账号 Cookie，不保证免短信。

列表按运行机器时钟切换查询阶段，成功快照有效期与该阶段查询超时一致。列表遇到普通错误时自行重试，主线程仍可用未过期的成功快照筛选和复核。“我的活动列表”在登录／重新认证、进入快抢期预热、待确认核对和预约确认成功后刷新。每次请求预算 8 秒，快照不按年龄淘汰。首次取得可靠结果后，主线程沿用最近结果。快抢期预热只发一次异步通知，进入快抢期时主线程另做一次普通列表读取，为验证码预取和提交共用的会话建立可复用连接；这次读取失败不影响预取排程。提交前不另行刷新，也不等待进行中的我的活动刷新。学校网页上的手动变更可停止再启动账号来同步。

验证码预取按运行机器的时钟安排在学校公布的预约开放前 2.7 秒。已知开放时间并取得首次可靠结果后，列表临时失败时仍可按时预取。验证码线程负责取图和识别，主线程取得可用列表后才判断是否提交。单次预取预算和预取快照有效期均为 8 秒。现场取图超时和对应的本地有效期为普通期 10 秒、开抢期 8 秒。学校实际有效期尚未测定。

每个候选一轮扫描最多四次取图识别／提交尝试，取图临时失败和预取码被判错也计入。取图临时失败、识别无效或学校明确判错时换码。用完本轮额度后处理其他候选或等下一轮，活动不进入冷却。

提交前先完整、原子地保存待确认的活动 ID 和时间。响应报成功仍须按 ID 核对；读取超时、未知回复或中断后也先核对。只有明确的非零整数错误码，配合验证码错误或不可预约文案，才能直接结束该次待确认。

## 状态与恢复

| 状态或情况 | 规则 |
| --- | --- |
| 提交结果待确认 | 暂停其他提交，两路查询各自按活动 ID 核对。任一路可靠的已预约记录即可确认，撤回或矛盾记录不能确认成功 |
| 查不到待确认活动 | 缺席不等于失败。连续三次有效的双来源核对仍未出现时，保留独立时间占位，再恢复扫描 |
| 一次有效缺席核对 | 列表和我的活动查询都须在本次核对开始后发起，至少间隔两秒；任一路失败或结果矛盾则重新计数 |
| 时间占位 | 参与冲突检查；占位期间原活动最多再提交两次。按运行机器的时钟，在占位建立后 600 秒或活动开始举办时取较早者到期 |
| 成功但我的活动列表尚未同步 | 保留已确认占位和参考计数，避免重复或冲突预约 |
| 临时网络、响应格式错误、OCR 无效、验证码判错或超时 | 各线程继续执行自己的计划。失败的一路按正常查询节奏或本轮尝试规则重试，不触发跨线程退避或活动冷却 |
| HTTP 429、有效 `Retry-After` 或 HTTP 502–504 | 429 或有效 `Retry-After` 共同约束后续学校请求。502–504 无有效等待指令时，后台查询线程在本线程短退避，直接同步适配器下由主线程短退避；取图按本轮额度重试，认证或提交按自身规则处理 |
| 状态损坏、账号不符或恢复时间非法 | 保留文件并停止，先备份和核对，不自动删除重建 |
| 停止或重启 | 保留任务、待确认、占位和已标明来源的服务器退避。启动时按已保存的占位建立时间和活动举办时间重算占位期限。旧验证码冷却和未标明服务器来源的退避不再执行。停止或删除本地数据不会取消学校预约 |

**没有超时退避，不代表可以重复提交结果不明的预约。** 人工核对入口见[入口与恢复](usage.md#入口与恢复)，不要删除 `task.json` 来绕过保护。

## 邮件与告警

邮件可关闭，关闭后仍记录本地事件。网页账号填写收信邮箱后，发送重要告警和每次成功通知；留空不发信，也不使用公共收件人。单账号 CLI 默认只发重要告警，`SEU_MAIL_SUCCESS=true` 可开启每次成功通知。

重要告警包括：需要人工认证、凭据被拒、查询或验证码／提交请求连续失败五分钟、异常退出。不发日报、目标达成、待确认或恢复邮件。

同一个尚未恢复的告警，跨重启也只尝试发送一次；发送失败不补发，不影响预约结果。成功通知按每次预约发送。邮件只含中文说明、安全汇总和时间，不含凭据、验证码或活动详情。邮件服务器接受不等于收件箱送达，配置见[邮件配置](usage.md#邮件配置)。

## 开发与验收

优先修复实战暴露的问题，保留最小有效回归，以及提交、待确认恢复、凭据保护和账号隔离检查。离线测试只能证明构造场景；命中率、验证码准确率和长期稳定性需真实运行证据。
