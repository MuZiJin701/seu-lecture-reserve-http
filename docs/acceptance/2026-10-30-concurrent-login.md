# 2026-10-30 同账号并发登录验证记录

本文记录同一学校账号从同一台 PC、同一网络出口同时建立两个独立登录会话的真实验证，供身份锁与只读检查策略的评估使用。记录已脱敏：不包含账号、手机号、凭据、Cookie／票据值、活动 ID、活动标题或完整个人活动列表；原始临时配置与日志已删除，不进入仓库。相关记录见[2026-10-29 只读对照](2026-10-29-read-only-probe.md)（约 90 秒后再次登录被拒发短信）与[2026-10-30 设备信任](2026-10-30-device-trust.md)（顺序静默登录）。

## 背景

- Web 管理台改造后，同一学校账号存在 CLI 与 Web 工作进程的互斥问题；只读 `--check` 是否也应被身份锁拦截，取决于学校是否允许同账号并发登录、后登录是否会顶掉先登录会话。
- 此前只有顺序样本：约 90 秒后再次登录时短信发送被拒；两次 `--check` 间隔约 60 秒时第二次靠持久 Cookie 静默登录成功。没有两个会话同时保持有效的样本。
- 本次目的：在同一账号、同一机器上保持会话 A 持续查询，再用独立进程完成第二次登录，观察两者能否并存、先登录是否失效。

## 测试条件

- 本机 Windows，Python 3.12 与锁文件依赖，工作树为当前暂存版本（登录与只读查询路径与 HEAD 一致；暂存改动只涉及 Web 管理台与设备信任 Cookie 的账号归属）。
- 两个独立进程，各自全新的 `requests.Session`、独立临时状态目录、独立密码＋短信登录；`SEU_TRUST_DEVICE=false`，不使用持久 Cookie，避免复用同一会话。
- 真实凭据从本机 `.env` 复制到隔离临时配置并覆盖状态目录；未修改仓库内 `.env` 以外的文件，测试后临时配置与日志已删除。
- 探针只调用只读接口：`queryMyActivityList.do`（我的活动）与 `queryActivityList.do`（活动列表），每 10 秒一次；不取验证码、不提交或取消预约、不发邮件、不写任务。
- 测试前确认本机没有正在运行的预约任务（`task_running=false`）；未修改 Clash/TUN、系统 DNS 或路由。
- 日志只记录事件名、时间、查询成功/失败与每次查询返回的条数，不含凭据、Cookie、票据、活动标题或 ID。

## 观测结果

- A 的第一次验证码被学校接受（CAS 登录成功），但随后进入应用页失败并触发一次 `campus_login_fallback`；回退的网关登录再次要求短信，因此 A 共使用 2 次短信完成认证。该现象与并发主题无关，作为附带观察记录。
- B 独立登录只需 1 次短信即成功；此时 A 的会话仍在持续查询。
- B 认证成功后，A 的后续查询全部成功；观察期内两进程合计约 50 次只读查询，**0 次认证失败、0 次查询错误**。
- 未观察到后登录使先登录会话失效（没有 `authentication_expired`、登录跳转或需要重新认证），也未观察到后登录被学校拒绝。
- 观察期内活动列表返回 0 条、“我的活动”返回 3 条，两进程结果一致；本文不记录具体活动内容。

## 结论

- 在本次条件下，**学校允许同一学校账号同时保持两个独立登录会话**；后登录未使先登录会话失效。
- 该结论用于评估“CLI 与 Web 工作进程互斥、只读 `--check` 是否也互斥”的策略：只读检查的会话安全理由不再充分，但开抢期额外登录带来的短信消耗与未知策略变化仍需保守处理。代码与需求尚未据此修改，最终决定见后续澄清记录。
- 不能据此推断预约提交链路、开抢期、多机多 IP、三个以上会话、长期并存或学校策略变化后的行为。

## 限制与边界

- 单账号、单机、单网络出口、非开抢时段、约 4 分钟、只读查询；未覆盖开抢窗口、验证码、提交、取消、邮件、跨天或长时间运行。
- 只有两个会话，未测试三个以上、不同设备或不同 IP 的并发，也未测试共享同一 Cookie 的克隆会话。
- 单样本观测；学校认证与会话策略可能变化，下一次结果可能不同，不能把本次结论写成保证。
- 未验证后登录对已提交预约、待确认核对或后台只读线程的影响。
- 临时探针、配置与日志已删除；本文不含账号、凭据、Cookie／票据值、活动 ID 或标题。

## 影响与后续

- 已决策（[ADR-0009](../adr/0009-concurrent-sessions-and-locks.md)）：移除账号身份锁与 `locks/` 目录，取消 CLI／Web 同号互斥；保留每账号状态目录的 `task.lock` 与数据根的 `manager.lock`，Web 内同账号仍只允许一个工作进程。使用指南与 Web 指南同步这一结论。
- 开抢期仍建议避免额外的诊断登录，避免短信冷却或未知会话策略影响运行中的任务。
- 如需更强结论，应另做多机／多 IP、开抢期与长时间并存的授权测试，并记录是否出现会话失效或短信拒绝。
