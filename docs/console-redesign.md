## 改版前已查明的实现边界

- 当前为 FastAPI、普通 HTML/CSS/JavaScript，尚无管理员登录；旧术语及 ADR-0008 的无登录取舍需要随新版方案更新。
- 已纳管账号的 Web 和 CLI `--account` 共用账号选项；旧单账号 CLI 另从配置文件读取选项。仅隐藏网页控件不会清除旧标题限制或覆盖旧开关值。
- 当前收信邮箱留空会关闭该账号邮件；启用邮件而公共 SMTP 无效会阻止正常启动，只读核对不受该校验影响。
- 页面已有选中账号与右侧详情，但配置在弹窗中；现有列表 API 只有候选筛选摘要和进度汇总，没有逐场已预约清单。
- 预约引擎在内存读取学校“我的活动”，当前约定不保存完整个人历史。逐场预约展示需要明确展示范围及最小本地快照，不能把候选或待确认占位当作已预约。

## 第一轮已确认（2026-10-30）

用户回复“1是2是3是的4是5是6留空就不发邮件呗7按照建议”，对应第一轮问题：

1. 全部管理员共享同一套学校账号并拥有相同操作权限；管理员仅通过服务器配置维护，不提供注册或网页增删管理员。
2. 继续仅在可信局域网 / VPN 内使用，保持 HTTP；管理员登录不改变传输协议或文件权限取舍。
3. 保留 FastAPI 与普通 HTML/CSS/JavaScript，参考提示不要求引入 React、TypeScript、Vite 或 Tailwind。
4. 采用浅色自然静态背景、磨砂玻璃、大圆角、黑色主按钮及轻微交互动效；Logo 以书页和时钟结合，由 Python 绘制。用户后续明确采用纯图案 Logo，图形内不放“听序”或其他文字。
5. 所有已有和新建的已纳管账号均清除标题筛选，并统一开启记住此设备、开抢前预热、验证码预取、后台历史刷新、开抢对齐及成功通知，网页隐藏相应开关；已纳管 CLI `--account` 同样生效。旧单账号 CLI 保留原配置能力。
6. 收信邮箱可留空，留空不发邮件；填写后自动开启重大告警与每次预约成功通知。公共 SMTP 无效时仍阻止启用邮件的账号正常启动；不改变只读核对与发信失败的处理边界。
7. 选中账号后展示学校记录中全部有效、尚未结束的预约，不限于本工具预约；字段为标题、类别、举办时间、地点 / 线上方式和预约状态。待确认提交及时间占位另行标识，不能算作预约成功；同时保留选听进度与配置编辑。

## 第二轮已确认（2026-10-30）

用户确认 Q8、Q10–Q13，并明确 Q9 无需热加载，`.env` 在启动前配置：

8. 管理员列表放在服务器 `.env`。后续用户明确要求直接填写用户名和密码，无需哈希命令；现同时支持普通密码与已有哈希，普通密码在启动时派生为内存哈希，配置原文不改写。未配置任何管理员时拒绝启动，不退回匿名访问。
9. 管理员配置仅在管理服务启动时加载，不做热加载。增删管理员及修改密码需要重启管理服务才生效；重启前旧配置和已有登录仍有效。重启沿用现有预约任务的安全停止与恢复机制，不清除任务或待确认保护。
10. 管理员登录采用固定 12 小时有效期，允许多个浏览器并存；退出仅结束当前登录，不停止学校账号预约任务；管理服务重启后全部管理员需要重新登录。
11. 选中卡片后直接在详情区编辑配置，点击保存才生效；桌面放在右侧，手机放在卡片区域下方。运行中保存沿用安全重启；切换账号时有未保存修改须提示是否放弃，自动刷新不覆盖正在输入的内容。
12. 当前预约清单复用预约引擎已有的学校查询，只保存展示所需的精简本地快照，显示同步时间；浏览网页不额外登录或查询学校。停止或查询失败时保留上次有效数据并标注状态；首次尚未查询显示“尚未同步”，不显示成零预约。
13. 多个管理员同时编辑同一学校账号时，拒绝旧表单覆盖已保存的新配置；提示重新加载，并保留未成功保存的输入。

## 实施范围与验收边界

- 未登录时显示登录视图；登录后进入唯一管理主界面。学校账号数据及操作接口均须通过管理员认证，静态登录资源可以公开；后台预约任务与管理员登录生命周期分离。
- 学校账号身份、密码不回显、创建后手动启动、运行中保存安全重启、短信人工认证、删除与待确认保护继续沿用现有规则。可编辑内容保留名称、学校密码、收信邮箱、类别、校区和线上 / 线下选择；已有一卡通号保持只读。
- 隐藏选项在服务端对全部已纳管账号统一生效，不能只删除前端控件；调整时保留凭据、原任务、待确认状态与时间占位。旧单账号 CLI 的标题过滤和可选开关保持原能力。
- 当前预约清单与选听进度分别展示；全部有效预约不等同于计入选听目标的待参加计划。待确认提交和时间占位单列，不作为已预约记录或成功证据；网页展示快照不替代预约引擎的核对证据。
- 验证覆盖匿名访问被拒绝、管理员登录 / 退出 / 到期 / 重启失效、配置校验、账号旧配置兼容、保存冲突、预约清单及陈旧状态、桌面和手机布局、未保存输入保护，以及现有预约引擎和生命周期回归。
- 使用临时配置、构造学校响应和模拟邮件做离线验证；真实学校登录、预约、SMTP 送达、Linux 部署和长期运行须分别记录，不能由离线结果推定。
