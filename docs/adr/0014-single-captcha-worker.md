# 所有预约验证码统一交给一个工作线程

2026-11-04 用户确认将预取、现场取图及验证码判错后的重新取图统一交给每账号一个验证码工作线程。本决定取代 [ADR-0013](0013-versioned-waits-and-captcha-preparation.md) 中“临时线程只做预取、现场取图仍由主线程执行”的分工，其余版本通知、等待、查询所有者和同步持久化约束继续适用。

首次需要验证码时启动一个 captcha-worker，后续任务复用该线程，空闲等待指令，不定时取图或建立验证码库存。只允许一个在途任务或一个尚未消费的结果；工作线程执行一次取图、图片校验和 OCR，将结果或异常交回主线程，不自行重试、不提交预约、不写任务检查点。任务编号递增并记录认证代次，旧认证代次的结果不得提交；认证失效后先归还主业务会话再重新认证。

取图继续独占借出的主业务会话，不假定跨会话验证码有效。期间主线程不认证、取图、提交或复制该会话新建读者；已有独立读者继续工作。主线程等待结果时消费新的可靠历史快照、处理读者错误、共享服务端等待、阶段参数、停止、邮件及健康状态。任务完成后只读取已有列表/历史快照，重算目标进度、候选和时间冲突；快照失效、已满或已有预约冲突时放弃当前提交，不为复核额外请求学校。

主线程决定派发时机、重试及提交；每候选最多四次尝试、开抢每场最多一次预取、提交前同步保存待确认检查点及不明确结果先核对的规则保持。预取沿用开抢前短预算；现场任务沿用普通期十秒、开抢期八秒预算，截止从派发开始计算，OCR 完成后再次判定预算和结果年龄。五秒结果有效期从收到图片时开始计算，是本地保守限制，不代表学校公布的有效期。

停止后不再派发新任务，尚未开始的任务可取消，在途任务归还会话后收尾，再关闭日志和会话。HTTP 使用有界读取，但 Python 线程、OCR 及底层本地调用不可硬中断，退出可能等待在途任务，不能承诺最坏停止时间。该方案改善主循环响应和处理逻辑一致性；现场取图仍是提交的前置依赖，不声称缩短取图本身或提高开抢命中率。

`--check` 保持独立的只读取图检查，不需要启动工作线程或 OCR；`background_poller=False` 的直接查询适配器继续同步执行，供离线构造时间与会话使用。生产 CLI 和管理台均使用默认后台模式。无新增依赖、配置、页面操作或频率选项。实现与真实验证分别记录在[本轮验收](../acceptance/2026-11-04-captcha-worker.md)。
