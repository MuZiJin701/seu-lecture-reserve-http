# 同一学校账号允许并发会话并移除身份锁

2026-10-30 同账号并发登录实测（单账号、同一 PC 与网络出口、两个独立进程并存约 4 分 22 秒、只读查询，见[验证记录](../acceptance/2026-10-30-concurrent-login.md)）未观察到会话互踢或后登录被拒：B 登录后 A 的查询全部正常，合计约 50 次只读请求无认证失败或查询错误。据此撤销“同一学校账号只允许一个运行实例”的身份约束。

决策：删除账号身份锁 `AccountLock` 与 `locks/` 目录，删除 CLI 与 Web 工作进程的同号互斥及 `account_already_running` 相关说明；同一学校账号允许在 CLI、Web 或不同机器上并发登录。保留的是数据一致性锁：每个账号状态目录的 `task.lock` 仍只允许一个进程写同一 `task.json`，数据根目录的 `manager.lock` 仍只允许一个 Web 管理服务，Web 内同一账号仍只允许一个工作进程。旧单账号 CLI 启动已纳管账号时仍提示改用 `--account`，这是操作提示，不是并发限制。

风险与边界：本次实测只覆盖单账号、单机、非开抢、约 4 分钟、只读查询，不能推断开抢期、多 IP、三个以上会话或提交链路的行为，学校的会话与短信策略也可能变化。重复预约仍由状态目录锁与待确认保护阻止；不同数据根目录的两套任务无法互相发现，也不能互相协调。开抢期仍建议避免额外诊断登录，以免短信冷却或未知会话策略影响运行中的任务。

账号进程边界见 [ADR-0003](0003-per-account-worker-process.md)，部署与账号操作见 [Web 指南](../web.md)，完整需求见[多账号与 Web 改造](../requirements.md#多账号与-web-改造)。
