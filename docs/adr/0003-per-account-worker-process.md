# 每个学校账号使用独立工作进程

2026-10-30 需求澄清第二轮，用户选择每个学校账号一个独立工作进程，分别持有学校会话、状态、人工认证等待和退避，让一个账号的阻塞或退出不拖住其他账号。相比同进程多线程，这一边界优先保障隔离和按账号控制生命周期；第四轮明确 10 个账号仅为并发验收目标，不设启动硬上限，OCR、线程及内存开销须通过离线与目标服务器实测验收，不将目标数当作已验证容量。

新增账号先保存、由管理员手动启动；服务重启恢复此前在运行的账号，已停止账号保持停止。第三轮进一步确认，运行中账号保存配置后仅安全重启该账号，沿用原任务及待确认保护；删除前先停止，存在待确认提交或保护占位时先完成核对。第四轮确认意外退出后有限次数自动重启，持续失败通知管理员，密码明确错误、状态损坏及人工认证等待不反复重启。本决策已实现，离线证据见 [HTTPS 版本离线验收](../acceptance/2026-10-30-web-offline.md)，完整需求见[改造澄清记录](../requirements.md#多账号与-web-改造)。
