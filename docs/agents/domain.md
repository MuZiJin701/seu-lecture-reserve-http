# 领域文档

本项目采用 single-context（单领域），没有多包或多领域目录：

- 根目录 [GLOSSARY.md](../../GLOSSARY.md)：领域术语及其含义。
- [docs/adr/](../adr/)：当前仍影响实现的设计取舍。
- [业务规则](../requirements.md)：已确认的产品行为，操作与参数通过其中的链接查阅。

## 读取与使用

探索业务前读术语表，再读相关需求和 ADR。Issue、方案、测试名称与用户说明沿用术语表的用词。发现方案与 ADR 冲突时，明确说明冲突和依据；涉及产品行为变化时先取得用户确认。

需要的领域文件缺失时，继续调查现有实现；术语或真实取舍明确后，再按 domain-modeling 技能补充。术语只定义概念，规则和操作各放在归属文档，通过链接引用；常规修复不新增 ADR 或验收报告。

## 旧文件迁移

发现根目录 `CONTEXT.md` 或 `CONTEXT-MAP.md` 时，先提示迁移：分别用 `git mv` 改为 `GLOSSARY.md` 或 `GLOSSARY-MAP.md`，并同步本文件及其他引用。新旧文件同时存在时先核对内容与合并方案，保留已有修改，不直接覆盖。

若以后出现真正的多包、多领域结构，再确认是否采用根目录 `GLOSSARY-MAP.md` 指向各领域术语表与 ADR；当前保持单领域。
