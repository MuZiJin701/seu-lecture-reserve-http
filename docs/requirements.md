# 讲座预约需求

截至 2026-10-26 的当前有效规则。本文整合历次访谈，只保留当前有效约定；历史版本由 Git 保存。实现和真实验收分别见[使用指南](usage.md#验收记录)，术语见 [GLOSSARY.md](../GLOSSARY.md)。

## 产品范围

- 单账号、单实例的 Python HTTPS 客户端，主要面向 Linux 服务器，兼容 Windows；认证和业务请求均校验证书。
- 目标固定为至少选听八场正式系列讲座或沙龙，其中法律、艺术、心理健康各至少一场；测试活动及购票公告不预约、不计数。依据学校记录统计，不要求手工维护次数，也不代替学院最终认定。
- 不区分年级，不提供三场目标、自定义次数、考核截止日、个人日历或跨机器协调。无候选时持续等待，直到实际达标或用户停止。
- 学校凭据、票据和完整个人活动记录留在仓库与日志之外；不自动取消预约、签到、评价或反馈。

## 目标统计与冲突

- 从学校“我的活动”读取进度，按活动 ID 去重；学校标记已打卡、未违约且未取消的四类系列讲座才可计为已选听。
- 有效且尚未结束的待参加预约可占用目标缺口；已选听加待参加覆盖总量和必需类别后暂停新增，继续核对。只有已选听本身达标才结束，预约一场成功后继续执行。尚未结束的预约缺少打卡/违约字段时按“未参加、未违约”处理并计入待参加；记录结束后仍无法确定状态时才暂停。
- 取消或学校确认违约后补足；所选记录已经结束，但尚未登记打卡或违约时等待学校确认，不立即补约。
- 未知状态或类别、矛盾重复记录、已提供总数不一致时暂停新增。没有分页信息或总数不能证明全历史完整，证据见[接口调查](completion-records.md)。
- 新预约与学校全部有效预约检查冲突，区间重叠及首尾相接均算冲突；已有预约状态、时间或列表完整性不明时暂停提交。
- 不同 ID 的已有记录重叠时，只为本地计数选择互不冲突的记录：优先已打卡，再优先补齐缺少的必需类别，然后按结束时间较早、活动 ID 排序；每次选择后更新缺口并排除冲突项。不承诺全局最多场数，链式重叠可选择互不冲突的多场。
- 该选择不修改学校记录，不把未选记录自行标为违约；未选的有效预约仍用于拦截新预约冲突。

## 候选筛选

- 支持完整标题、类别、校区、线上线下开关和冲突筛选。标题列表非空时完整匹配，空列表不限制；指定标题仍受其他条件约束，同名活动按不同 ID 处理。
- 默认允许线上，线下只允许明确配置的校区；空校区列表不约线下。默认类别及名称见 [.env.example](../.env.example)，不增加日期范围、每日可用时段或时长筛选。
- 列表中类别非空、有效且明确不在启用类别内时提前排除，不要求其余讲座字段完整。类别缺失或异常、目标类别记录仍严格校验；此例外不适用于已有预约及目标统计。
- 非目标类别诊断保留可用标题和预约时间；标题缺失显示空字符串，无法解析的预约时间显示未知。其他正常记录按首个命中的筛选原因解释，不把未知结构当作空列表。
- 目标讲座须校验发布状态、预约时间窗和明确的授课方式；未开放时也校验。起止时间无法解析则跳过该候选，资格与名额以学校活动列表的已约人数／总人数判定及提交后按活动 ID 核对为准。
- 候选同 ID 且内容一致时只处理一次，矛盾候选暂停本轮提交。优先补齐必需类别并为其预留缺口，再按配置类别顺序、线上优先、开始时间较早排序，最后按 ID 固定顺序。
- 已有记录导致必须超过八场才能满足类别时，仅补必要类别。标题列表不表示优先级，筛选配置不排除历史记录的目标统计。

## 认证、轮询与提交

- 认证通过后才开始业务查询与提交。会话失效先尝试恢复或重新登录，需要人工操作时进入待认证状态；明确凭据错误或账号受限后停止自动登录并通知。
- 前台通过 SSH 输入 `send` 主动发送或重发短信，再输入六位验证码；不自动反复发短信，不设固定等待截止时间。过期后由用户重新获取，未知挑战说明原因并等待。
- 正常查询间隔十秒；预约开放时间前三十秒至开放后十分钟内以 0.25–0.5 秒间隔顺序轮询，开抢期请求失败按快速间隔重试，发现候选后直接提交，不并发提交。开抢期优先保证活动列表轮询，历史记录查询失败不阻塞列表；开抢快窗口沿用开抢前 60 秒内的历史缓存，不在开放瞬间同步刷新；同时保留已知且未结束的开抢窗口，最新列表合法但暂时为空或缺少目标时仍按已知窗口维持快轮询，提交仍只依据最新有效列表。429/502/503/504 在读取响应体前按状态码与响应头判定；响应体按块读取，每次底层读取以剩余预算做 select 等待，gzip 解码与 chunked 分帧等内部连续读取同样受总预算约束，单次阻塞读取也以剩余预算作为 socket 超时；连接/首部仍只受 Requests 单次读取超时约束，不保证整请求总时限，属已知限制。连接阶段超时视为请求尚未发出，可安全恢复扫描；读取超时或已发送但结果未知的提交仍按待确认处理。调度以学校服务器时间校准本机时钟偏差。429 严格按 `Retry-After` 等待，收到 429 或带等待值的过载响应后先等待，再发起历史探测或其他业务请求；502/503/504 视为临时过载，按短退避恢复（无等待指令时约 1 秒起、上限 5 秒），持续失败再升级。异常指数退避，学校有效限流要求优先。非法或不可持久化的等待值使用本地退避，不写入无限等待。该频率仍需实测，不能据此保证预约成功。
- 候选可用性按学校前端同款判定：发布状态、预约时间窗（以学校服务器时间为准）、已约人数与总人数（满员即跳过）；不再调用不可靠的预约前检查接口。提交结果以提交响应与按活动 ID 核对为准。
- OCR 输出只接受非空 ASCII 字母数字及现有长度限制。验证码明确错误或识别无效时，初次尝试外最多重新取图三次；仍失败则该场冷却五分钟，尝试其他候选。
- 每次提交前持久化待确认活动 ID、首次待确认时间与连续核对次数。响应成功也须按 ID 查询确认；超时或未知结果先多次核对原活动，期间不提交其他场次。连续 3 次有效查询仍未见原活动时，按“原提交未生效”自动解除待确认并恢复扫描，允许按最新列表重新选择；学校对同一活动的重复预约应由业务拒绝，程序记录 `reservation_unconfirmed_released` 事件供事后核对。查询失败、记录矛盾或结构不完整时保持待确认并继续核对，不据此自动解除；`--resolve-pending` 保留为人工兜底入口；不发送待确认通知。
- 只有非零整数返回码且文案明确时，才可将提交响应认定为验证码错误或不可预约；缺失、空值、字符串或布尔码不能仅凭文案清除待确认状态。
- 首次登录的网关连接可按配置回退一次备用 IP，触发条件及限制见[网关回退](usage.md#网关回退)；不重放预约请求、不降低证书校验。

## 状态与恢复

- 同一状态目录通过文件锁限制一个实例；同账号在其他机器或浏览器版的实例须由用户停止。
- 正常启动始终认证并重查学校进度，即使本地任务已完成：仍达标就结束且不重复通知，不足则恢复扫描，再次达标时通知。
- `--new-task` 仅为重新核对已完成任务的兼容入口，不额外多约一场，不允许重置扫描或待确认任务。
- `--resolve-pending` 是待确认提交的人工兜底入口：停止运行中的实例后使用；只读查询“我的活动”，原场已出现则确认成功，未出现时必须由操作者显式输入确认短语才清除待确认；取消不改变状态；不发送提交请求。正常自动解除不依赖该命令。
- 重启保留待确认提交、待确认核对次数、冷却和退避；学校时间尚未校准时，保留并继续拦截已有冷却，不按本机时间判定到期；后续列表或慢路径复核缺少学校时间时沿用已知偏差。版本 1 单场任务自动迁移到版本 2 的目标任务。损坏状态、通知历史、非法恢复时间或账号不符时保留原文件并停止，不用新快照覆盖错误。
- 状态采用私有权限、原子替换和持久化写入；停止、SIGTERM 和 Ctrl+C 保留任务并释放锁，不取消预约。强制终止、断电无法保证退出通知。
- `--status` 离线显示本地状态及快照时效，不以 PID 文件或 `scanning` 判活；任务锁、阶段和成功查询时间共同提供运行证据，不能代替学校结果。
- `--check` 与扫描共用字段校验和筛选，展示逐场标题、首个原因及预约时间；不使用本地冷却，不创建或迁移任务，不提交、取消或发邮件。正常扫描的私有诊断快照跨重启保留；旧快照标注时间，不为诊断额外查询。
- 当前列表的必要筛选详情仅留在本地状态与终端，不进入事件日志或邮件，不保存完整个人历史。
- 私有诊断写入状态目录的 `diagnostics.jsonl`：扫描节奏、筛选变化、验证码、提交、核对结果、自动解除与预约关键步骤失败；字段脱敏、只追加，不进入终端、邮件或事件日志；不自动轮转，由用户按磁盘情况清理。

## 邮件与告警

- 邮件是唯一主动通知渠道，可关闭；关闭后仍记录终端和本地事件。只读检查不校验邮件配置；独立 `--test-mail` 只发一封测试邮件，不访问学校或修改任务。
- `qq.com`、`163.com`、`126.com`、`gmail.com` 按域名精确匹配，大小写不敏感；仅需完整邮箱地址及授权码或应用专用密码，默认发给自己。非空显式主机、端口、发件人与收件人优先；其他域名需手动配置。
- 邮件字段全空或缺省时关闭，仅保留 `SMTP_PORT=465` 也关闭；部分配置不完整或无效则报错停止启动。使用校验证书的隐式 TLS，兼容无需认证的 TLS 中继；不增加明文、STARTTLS 或 OAuth。
- 只在重大问题尝试通知：需要人工认证、连续五分钟无法完成查询、连续五分钟无法完成验证码或提交请求（预约关键步骤失败）、可捕获异常退出、程序异常退出；预约成功通知受 `SEU_MAIL_SUCCESS` 控制，开启时每次经活动 ID 确认的预约成功发送一封，由后台线程发信、不阻塞扫描，关闭时不发；不发目标完成、待确认、恢复通知或日报。通知失败不改变预约结果，不触发重复预约。
- 同一未解决告警在发信前保存，跨重启只尝试一次；失败或结果不明不自动重发；问题解决后出现新问题可重新告警；恢复只记录，不再发信。关闭邮件不消费新的持久邮件配额。
- 持续查询失败从首次失败起计时，满五分钟后尝试通知一次；等待期间照常重试，告警不延后业务查询或退避；开抢窗口内延后到窗口结束再发送，期间恢复则不发送；查询恢复不发送恢复邮件。验证码或提交请求的连续失败单独计时（列表查询成功不清除），满五分钟通知一次；提交返回可判定结果、预约成功或不再有候选时视为恢复；同在开抢窗口内延后并去重，恢复不发送恢复邮件。
- 邮件使用中文说明和处理建议，包含最近核对的已选听、待参加、类别缺口、数据及查询时间、安全错误码和检查计划；未知进度不能写成零。不含讲座标题、学校凭据、验证码、票据或完整活动记录。
- 复用同步 SMTP，记录发送事件、实际耗时与固定错误分类，跨重启保留最近结果；不输出异常原文、SMTP 响应或邮件地址，不新增线程、队列和补发。SMTP 接受和收件箱送达分别判断。

## 配置、入口与服务器运行

- 登录、筛选、状态目录及邮件统一用 `.env`；默认只加载当前目录文件，进程环境变量优先，显式配置文件不存在即报错，状态目录相对于配置文件。只提交配置样例，不改写全局环境。
- 推荐 `uv run --locked main.py`，保留 `uv run main.py` 和 `seu-reserve` 入口；参数与退出码一致。启动、只读检查和测试邮件各展示一次维护者及项目链接，轮询不重复，状态与帮助保持简洁。
- Ubuntu 24.04 后台改用系统级 `systemd-run` 临时服务，名称 `seu-lecture-reserve-http`，以安装账号和项目工作目录运行；限制文件权限，保留追加日志和停止等待。SSH 断开继续，退出或服务器重启后手动启动，不自动重启、不自启。
- 服务不自动继承 SSH 临时环境。业务配置仍使用 `.env`；代理按需显式传入，不新增自动透传或 `.env` 代理字段，保留原环境优先级。
- 后台无交互终端而需要人工输入时，保留任务并退出；确认退出后前台处理。迁移旧 `nohup` 实例先核对命令、PID 和目录再停止，保留状态。使用文档提供检查、启动、查看、停止及恢复步骤。
- 双语 README 使用简洁步骤，全部配置先于首次运行；使用指南集中配置、排错和验收。全部文档核对并瘦身，历史截图和宣传素材不作为当前运行或验收证据。
