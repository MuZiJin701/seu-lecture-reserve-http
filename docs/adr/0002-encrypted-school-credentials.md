# 加密持久化学校凭据（已取代）

第四轮用户明确改为不加密，最新决策见 [ADR-0005](0005-local-plaintext-school-credentials.md)。以下仅保留第二轮的取舍背景，不再作为实施依据。

2026-10-30 需求澄清第二轮，用户选择在服务器加密保存每个学校账号的密码和登录 Cookie，解密密钥独立放在服务器 `.env`；网页允许替换学校密码，不返回已有密码原文。相比每次启动重新输入，此选择支持服务重启后的账号恢复及会话失效后的重新登录，同时要求备份与迁移时同时考虑密文和密钥；密钥丢失、轮换与恢复细则尚待澄清。

这是尚未实施的 Web 改造决策；加密不替代服务器访问控制，也不意味着管理员网页应提供学校凭据读取接口。完整需求见[改造澄清记录](../requirements.md#多账号与-web-改造)。
