# 使用与验收

首版为 Python 3.12 的单账号同步客户端。目标口径依据[需求 Q22](requirements.md#q22中期考核讲座目标2026-10-16)，运行改造见[需求 Q28–Q33](requirements.md)，初始规格见 [Spec #1](https://github.com/MuZiJin701/seu-lecture-reserve-http/issues/1)，不依赖浏览器。

## 安装与离线检查

```bash
uv sync --locked
uv run --locked mypy seu_reserve
uv run --locked pytest
uv run --locked main.py --help
```

依赖安装到项目隔离环境；OCR 使用 ddddocr，模型随依赖包提供。首次安装包含 ONNX、图像依赖和模型，下载量较大。
`tzdata` 提供 `Asia/Shanghai` 时区数据，兼容 Windows 等没有系统 IANA 时区库的环境；更新依赖及锁文件后需重新运行 `uv sync --locked`，避免启动时出现 `ZoneInfoNotFoundError`。
测试只使用构造的学校响应、临时时间/文件、人工输入和邮件替身，不加载真实账号配置，不访问学校，不发送真实邮件。

Windows 使用标准库 `msvcrt` 文件锁，Linux 使用 `fcntl`；二者都阻止同一状态目录并发运行。Windows 保留状态文件的 `fsync` 与原子替换，不执行 Linux 的目录 `fsync`。Windows 分支已做离线模拟验证，真实 Windows 运行及断电恢复仍待验收。

## 配置与凭据

```bash
cp -n .env.example .env
chmod 600 .env
# 编辑 .env，填写登录信息、筛选及可选的邮件配置
uv run --locked main.py --status
```

请将 `.env` 和状态目录放在仅自己可访问的目录中，已有配置不需要重新复制。

登录、筛选、状态目录和邮件统一放入 [.env.example](../.env.example) 对应的 `.env` 文件，程序默认自动读取**当前工作目录**的 `.env`，不向上搜索其他目录。
在其他目录运行时，用 `--config /项目目录/.env` 明确指定文件。显式指定的文件不存在会报错，不回退读取其他文件。
状态目录相对于所选 `.env` 所在目录；默认名称为 `state`。进程环境变量优先于文件，不会把文件内容写回全局进程环境。

| 配置项 | 含义 |
| --- | --- |
| `SEU_CARD_NUMBER` / `SEU_PASSWORD` | 一卡通号 / 密码，与旧项目命名一致 |
| `SEU_PREFERRED_LECTURES` | 完整标题列表，`'[]'` 表示不限标题 |
| `SEU_REQUIRED_CATEGORIES` | 类别 JSON 数组，省略时使用心理、法律、艺术、其他四类及顺序；不预约沙龙，不能是空数组 |
| `SEU_PREFERRED_CAMPUS` | 允许的线下校区 JSON 数组，`'[]'` 表示不约线下 |
| `SEU_ENABLE_ONLINE` / `SEU_ENABLE_OFFLINE` | 是否允许线上 / 线下，值为 `true` 或 `false` |
| `SEU_STATE_DIR` | 任务状态和日志目录，默认 `state` |
| `SEU_VPN_IP` | 首次登录的备用网关 IP；先使用正常 DNS，符合条件的连接故障触发一次回退；缺省或空值关闭回退 |

列表是 JSON 数组，外层用单引号，例如 `SEU_PREFERRED_CAMPUS='["无锡校区"]'`。
标题完整匹配仍受其他筛选及冲突规则约束；真实列表只接受标题开头明确的 `【线上】`／`【线下】` 标记，兼容旧格式的显式布尔字段，不按标题中任意位置的文字猜测。
密码等字符串含空格、`#`、`=` 或 `$` 时可以按示例用引号包裹。`${...}` 原样保留，不做变量展开；`.env` 由 Python 读取，不需要也不要作为 shell 脚本执行。
真实 `.env` 和 `.env.*` 已被 Git 忽略，仅提交不含凭据的 `.env.example`。

为保留此前的使用方式，也接受 `SEU_USERNAME`；同一来源同时有它和 `SEU_CARD_NUMBER` 时后者优先，任何进程环境中的账号设置都优先于文件中的账号设置。
未填写登录信息时仍可在交互终端隐藏输入；非交互运行缺少凭据时直接报错。

邮件通知可选。不填写邮件配置也能正常预约，成功、需要人工认证、持续异常或结果待确认时仍记录终端和本地事件，但不会主动发信；需要自己查看终端和日志。

Gmail 只需填写 `SMTP_USERNAME`（完整的 `@gmail.com` 邮箱地址）和 `SMTP_PASSWORD`（应用专用密码），其余配置自动补全，默认自己给自己发邮件。设置方法见下方 [Gmail 示例](#gmail-示例)。

以下字段保留为高级配置，非空的显式值优先于自动补全；已有完整配置仍可使用，包括无需认证的 TLS 中继：

| 变量 | 含义 |
| --- | --- |
| `SMTP_HOST` | SMTP TLS 主机；Gmail 默认 `smtp.gmail.com`，其他邮箱及自定义域名需手动填写 |
| `SMTP_PORT` | 隐式 TLS 端口，默认 465 |
| `MAIL_FROM` / `MAIL_TO` | 发件人默认取 `SMTP_USERNAME`；收件人默认取发件人 |
| `SMTP_USERNAME` / `SMTP_PASSWORD` | SMTP 认证，需成对提供；允许无需认证的 TLS 中继 |

首版使用 SMTP 隐式 TLS，不提供明文连接或 STARTTLS 模式。邮件包含中文事件说明、处理建议、最近核对的汇总进度、数据时间及安全错误码，不包含学校账号、讲座标题、验证码、票据或完整个人活动记录。

邮件启用后用于提醒预约成功、选听目标完成、需要人工认证、持续异常及预约结果待确认，不读取收件箱，也不代替手机短信验证。收到认证提醒后，仍需回到 SSH 终端处理。正常等待除每日汇报外不发送邮件；只填收件邮箱不能完成发信配置。

正常运行中的可捕获异常退出也会记录事件并尝试发信，明确凭据拒绝使用原有专用通知，不重复发两封。主动 `Ctrl+C` 或 SIGTERM 停止不作为异常通知；强制杀进程、断电或邮件服务不可达时，程序无法保证通知。没有收到邮件不代表运行正常，应同时检查本地运行信息。

所有邮件字段缺省或为空时关闭邮件；单独保留旧样例中的 `SMTP_PORT=465` 也视为未启用。要关闭已有邮件通知，清空 `SMTP_USERNAME`、`SMTP_PASSWORD`、`SMTP_HOST`、`MAIL_FROM` 和 `MAIL_TO`，并将 `SMTP_PORT` 留空、删除或保留为 `465`；进程环境中的同名配置也需清除。

尝试配置但缺项、邮箱格式错误、无法确定 SMTP 主机或端口无效时，显示 `event=mail_configuration_invalid` 并停止启动。Gmail 的账号与应用专用密码需同时填写；其他邮箱需提供 `SMTP_HOST`，发件人与收件人必须可确定。只读 `--check` 不检查邮件配置，也不发送测试邮件。实际发信失败仅记录 `notification_failed`，不会改变预约结果或触发重复预约。

从此前 TOML 方式迁移时，按新 `.env.example` 填入对应字段即可；TOML 配置入口已移除，已有个人 `config.local.toml` 不会被删除。
旧 Playwright 项目的浏览器专用超时参数不适用于本项目，不要原样复制整个旧 `.env`；正常轮询仍为已确认的 10 秒。

### Gmail 示例

先为 Google 账号开启[两步验证](https://myaccount.google.com/signinoptions/two-step-verification)，再创建[应用专用密码](https://myaccount.google.com/apppasswords)。为本工具命名并生成密码，复制 16 字符密码、去掉分组空格，将以下两项填入本机 `.env`：

```dotenv
SMTP_USERNAME=your-address@gmail.com
SMTP_PASSWORD='your-app-password'
```

将邮箱和应用专用密码占位值替换为自己的值。程序自动使用 `smtp.gmail.com:465`，发件人与收件人均为上述邮箱；若旧文件仍有 `SMTP_HOST`、`SMTP_PORT`、`MAIL_FROM`、`MAIL_TO`，请清空或删除这些项以使用自动补全。服务器与端口见 [Google SMTP 文档](https://developers.google.com/workspace/gmail/imap/imap-smtp)；本客户端使用应用专用密码，不填写 Google 账号的日常登录密码。
若页面显示“您的账号不支持您正在尝试的设置”，先确认两步验证已开启；组织账号、仅使用安全密钥的两步验证或高级保护计划也可能限制此功能，见 [Google 官方说明](https://support.google.com/accounts/answer/185833?hl=zh-Hans)。不要为了配置邮件关闭账号安全保护。
配置格式通过检查不代表邮件已送达；服务器还需要能连接 Gmail 的 SMTP 服务。`--check` 不发送测试邮件。

### 单独测试邮件

```bash
uv run --locked main.py --test-mail
```

读取同一 `.env`，只发送一封固定事件 `test_notification` 的邮件，不要求学校账号密码、不访问学校、不创建或重置预约任务。该参数与 `--check`、`--status`、`--new-task` 互斥。

| 输出事件 | 退出码及含义 |
| --- | --- |
| `test_mail_accepted` | 0，SMTP 服务器已接受邮件；仍需在收件箱及垃圾邮件目录核对送达 |
| `mail_disabled` | 1，没有启用邮件配置 |
| `mail_configuration_invalid` | 1，邮件配置不完整或格式无效 |
| `notification_failed reason=...` | 1，发信失败；仅输出下表固定分类，不输出服务器响应、邮箱或密码，不自动重发 |

测试入口不更新预约任务中的 `mail_status`，该字段仅记录任务自身的通知状态。SMTP 接受不能证明收件箱已收到，也不能证明讲座预约已验收。

## 邮件通知与每日汇报

启用邮件后，单场预约成功、目标完成、人工认证、预约待确认、连续三轮查询／处理失败及可捕获异常退出会尝试通知。重要邮件使用中文说明和处理建议，附最近核对的已选听／待参加数量、含计划的必需类别缺口、进度时间、最近成功查询、安全业务错误码、连续失败次数和下次检查计划。成功通知采用本轮确认后的进度；没有数据或计划时明确显示未知或尚未安排。历史错误码可以保留，并不代表仍在故障。

认证受阻、预约待确认和连续失败的告警在发信前保存；同一未解决问题跨重启只尝试一次，发送失败或结果不明不自动重发。问题解决后清除对应告警。关闭邮件仍记录本地事件，但不消费新的持久邮件告警配额。

连续失败告警后，首次完整恢复当前所需查询／处理时记录 `query_recovered` 并尝试通知一次，可接续重启前的告警；仅登录或部分读取成功不算恢复。待确认模式的查询恢复不代表预约成功，也不能解除暂停其他提交的保护。短暂失败或没有故障告警记录时不发恢复邮件。

两次查询失败告警至少相隔十五分钟，间隔跨重启保留；同一持续故障仍只提醒一次。间隔内出现的新故障持续到期后，在随后失败检查时告警；不推迟学校查询和既有退避，也不限制人工认证或待确认告警。

运行且启用邮件时，每天北京时间 **20:00** 汇报。当天 20:00 后启动，在首次安全等待时尝试当天汇报，不补历史日期；同一状态目录每天最多尝试一次，发送前保存，重启不重复，失败不补发。只读检查、停止和目标完成退出后不继续汇报。等待或退避可在 20:00 唤醒发信，但不提前查询学校；终端人工输入、业务请求或提交期间可延迟到安全等待点。

汇报使用最近核对的进度并标明时间；旧数据不能当作实时数据，未取得数据时显示未知，不把查询失败当作零场。重启后尚未核对的进度也为未知。邮件不含讲座标题或完整个人活动明细。

发信继续在主线程同步执行，每次尝试记录实际耗时。网络操作的 20 秒超时不是整封邮件的总耗时保证；若运行记录表明影响扫描，再评估发送线程，本轮不新增队列或自动重发。邮件故障不改变预约结果、不触发重复提交；SMTP 接受不证明收件箱送达。

`--test-mail` 与运行通知使用相同的安全错误分类；不打印异常原文、邮件地址、SMTP 响应或凭据：

| `reason` | 含义 |
| --- | --- |
| `dns_failed` | 邮件服务器 DNS 失败 |
| `connection_failed` | 连接失败或断开 |
| `tls_failed` | TLS 握手或证书错误 |
| `timeout` | 网络操作超时 |
| `authentication_failed` | SMTP 认证失败 |
| `sender_refused` / `recipient_refused` | 发件人／收件人被拒绝 |
| `message_rejected` | 邮件正文被服务器拒绝 |
| `smtp_failed` | 其他 SMTP 错误 |
| `network_failed` | 其他网络／系统错误 |
| `unknown` | 无法归类 |

## 先做只读检查

```bash
uv run --locked main.py --check
```

该命令认证后查询列表、我的活动并获取校验验证码图片；列表非空时使用与正常扫描相同的解析器和筛选规则，输出逐场 `activity_details`，说明首个筛选原因与预约时间窗；不读取本地任务冷却。不提交或取消预约，不创建预约任务，也不发送邮件。
成功退出码为 0，终端显示 `event=read_only_complete`；失败退出码为 1。认证需要短信时仍须人工处理。
检查失败时会输出阶段与安全错误码，例如 `event=task_failed stage=authentication reason=http_failure http_status=403`。阶段依次为 `authentication`（登录认证）、`my_activities`（我的活动）、`activities`（讲座列表）、`captcha`（预约验证码）。排查时提供这一整行；诊断不输出凭据、票据、完整 URL 或响应正文。

| 错误码 | 含义 |
| --- | --- |
| `tls_failure` | TLS 握手或证书校验失败 |
| `proxy_failure` | 代理连接失败 |
| `network_timeout` | 连接或读取超时 |
| `connection_failure` / `network_failure` | 连接失败或其他请求异常 |
| `http_failure` / `server_backoff` | HTTP 请求失败或服务要求退避，同时显示 `http_status` |
| `authentication_rejected` | 认证明确拒绝账号或密码 |
| `activity_schema_unknown` | 讲座列表关键字段、线上线下标记、发布状态或预约时间窗未知；不要当成无可约讲座 |

TLS 失败会额外显示 `host`（通过白名单校验的学校域名）、`tls_reason` 和可确定时的 `proxy_used=true/false`（Requests 是否选择了代理，不输出代理地址或凭据）。`tls_reason` 只输出预设类别，无法识别时为 `unknown`：`certificate_verify_failed` 表示证书校验失败，`unexpected_eof_while_reading` 表示 TLS 连接意外中断，`unsafe_legacy_renegotiation_disabled` 表示旧式 TLS 重协商不兼容；其他握手类别按原错误码的小写形式输出。不要把所有 `tls_failure` 都归因于代理。

此检查验证接口读取、已有记录的选听统计字段、当前非空讲座列表的字段及图片解码。列表为空时不能证明讲座字段兼容，尚未开放的列表也不能证明开放时预约会成功。检查不创建或迁移任务，不提交预约；不能证明所有学期记录完整、OCR 准确率或真实预约已经验收。

### 仅在项目内绕过网关 DNS 故障

本机网络的 DNS 或 TUN 内部解析可能对 `vpn.seu.edu.cn` 返回 NXDOMAIN，即使公共 DNS 能返回有效地址。TUN 接管连接后无法解析真实 IP 并关闭连接，客户端也可能显示 `tls_reason=unexpected_eof_while_reading`。备用 IP 用于尝试恢复这些连接故障，不表示所有 TLS 错误都由 DNS 引起。

`.env.example` 已预填以下备用 IP，复制样例即可使用；升级时保留已有 `.env`，如需启用回退，手动添加或取消注释该项：

```dotenv
SEU_VPN_IP=121.249.14.2
```

即使填写了备用 IP，也先使用正常 DNS。只有首次登录阶段访问 `vpn.seu.edu.cn` 时遇到解析失败、连接关闭或重置、可识别的 TLS 意外断开，才改用备用 IP 并重新走认证流程一次。普通连接或读取超时、连接被拒绝、未知连接错误、证书校验失败、账号密码错误、代理错误、HTTP 错误和其他域名故障不触发回退。回退仍失败时走原有报错或退避流程，不在 DNS 和 IP 间反复切换。

回退后，本次进程持续使用备用 IP，下次启动重新尝试正常 DNS；首次登录成功后不再新增自动切换。此机制只重新进入认证流程，不直接重放失败请求，也不重放预约提交；提交结果不明时仍先查询原活动。

程序仅在回退时替换 `vpn.seu.edu.cn:443` 的连接地址；请求 URL、HTTP Host、TLS SNI、证书域名校验和 Cookie 仍使用原域名。其他学校域名、系统 DNS、代理及 TUN 设置不变，Requests 的环境代理仍然生效，因此不能保证绕过所有代理或 TUN 干预。IP 必须是有效的 IPv4 或 IPv6 字面地址，不接受域名、URL 或端口；进程环境变量优先于 `.env`。

程序内部没有默认备用 IP；删除该配置或设为空值后，仅使用正常 DNS。程序不自动查询公共 DNS。示例地址来自 2026-10-16 的排查记录，可能变化；失效时向可信 DNS 核对该域名的 A/AAAA 记录后更新，再运行 `uv run --locked main.py --check`。不建议将回退扩展到其他学校域名，它们可能需要校内 DNS。真实 DNS 或 TUN 故障恢复仍待验收。

## 运行诊断

`--check` 展示当前列表的逐场诊断；正常轮询保持安静，只把最近一次成功筛选结果保存到私有 `task.json`，用 `--status` 查看 `activity_details` 与 `selection_updated_at`。每场只展示标题、首个命中的原因及学校提供的预约开放／截止时间（北京时间）；缺失时间为 `null`。

| 原因 | 含义 |
| --- | --- |
| `candidate` | 通过当前筛选，仍须预约前检查及提交确认 |
| `reservation_not_started` / `reservation_ended` | 预约时间尚未开始／已经结束 |
| `capacity_full` / `not_reservable` | 旧显式格式标记已满／当前不能预约；真实列表的名额仍由前检查判断 |
| `already_reserved` | 列表标记或“我的活动”已存在预约 |
| `category_not_allowed` / `category_not_needed` | 类别不在配置中／当前目标无需该类别 |
| `title_not_selected` | 不满足配置中的完整标题 |
| `online_disabled` / `offline_disabled` | 配置关闭对应授课方式 |
| `campus_not_selected` | 线下校区不在配置范围 |
| `time_conflict` | 与学校有效预约重叠，首尾相接也算冲突 |
| `cooldown` | 此活动处于本地验证码失败冷却期；只读检查不使用此记录 |
| `invalid_activity_time` | 活动时间无法解析，跳过该场；已有预约时间不明则阻止新增 |

快照跨重启保留，但等待打卡、处理待确认结果或查询失败期间可能不更新，必须结合快照时间判断，不能冒充最新学校结果，也不为诊断额外查询列表。空列表和未开放列表不证明真实预约链路已验收。未知结构明确报错，不能显示成普通零候选；同 ID 完全一致的候选去重，矛盾候选暂停本轮提交。

状态文件和 `--check`／`--status` 输出可能含讲座标题，请仅在本地查看；逐场详情不进入事件日志和邮件，公开排错时只提供安全事件码。状态不保存凭据、票据或完整个人活动记录。

## 运行和恢复

```bash
uv run main.py
```

推荐入口为项目根目录的 `main.py`，复用 `seu_reserve.cli.main`，参数和退出码一致。`uv run --locked main.py` 额外要求锁文件与依赖声明一致，否则报错，不会自动更新锁文件；原 `uv run --locked seu-reserve` 仍兼容。

此命令会对符合条件的候选提交真实预约。默认每 10 秒查询，异常时退避（20、40、80 秒，最多 300 秒），学校明确的 Retry-After 优先。
先补齐法律、艺术、心理健康中缺少的类别，再按配置类别顺序、线上优先、开场较早选择。预留缺少类别的名额，不用其他类别填满 8 场后再超量补课。用户已有记录使总数必须超过 8 才能满足类别时，仅补必要类别。冲突检查包含首尾相接；已有预约状态或时间不完整时停止本轮提交。

按活动 ID 去重，统计学校“我的活动”中未取消、未违约且 `SFDK='1'` 的四类系列讲座。`JZXL_DISPLAY` 是真实历史类别字段，兼容构造响应的 `HDLX_DISPLAY`；沙龙不计入，即使旧 `.env` 的类别列表保留沙龙也不会预约它。已打卡次数至少 8 且法律、艺术、心理各至少 1 才结束；既有调查中，默认列表与学校“已打卡”筛选的样本核对一致，但未证明所有学期和其他渠道记录均完整，见[接口调查](completion-records.md)。

不同活动 ID 的已有记录若时间重叠，程序不因重叠本身暂停，而是自动选择互不冲突的场次计入本地完成次数或待参加计划。每次先选已打卡且未违约的场次，再优先补齐当前缺少的必选类别，然后按结束时间较早、活动 ID 的顺序选择；选中后更新类别缺口，并排除与它冲突的统计候选。首尾相接也算冲突。A 与 B 重叠、B 与 C 重叠而 A 与 C 不冲突时，可以同时计入 A 和 C。选择按上述优先级逐次进行，不做全局最优排课。

选择只影响本地统计，不取消、修改学校已有预约，也不自行标记其他场次违约；学校最终认定可能与本地选择不同。未选中的预约仍用于拦截新的冲突预约，未打卡的场次仍不能计为已选听。程序每轮根据学校最新记录重新计算。

成功预约一场后通知并继续，不再直接结束。所选已打卡加尚未结束的有效预约覆盖目标时，每 10 秒核对“我的活动”，暂停新预约。取消或学校标记违约后重新计算缺口。所选记录已结束但既未打卡也未标记违约时，先等待学校更新，不能自行断定缺席。全部记录仍须通过原有字段与时间校验，未知字段、矛盾重复记录阻止新增；不猜测类别，不自动取消、签到或评价。

每次提交前先原子保存待确认活动 ID。超时或响应无法解释时先查询原提交，期间不提交第二场；持续不明确时通知并等待人工处理。
异常等待截止时间会一并持久化，重启后先等完剩余时间，避免绕过学校限流。过期冷却记录会清理。
等待时按回车只会重新查询，不会把用户按键当作“预约失败”的证据。不要手工删除待确认任务来绕过保护。
明确验证码错误时最多重新取图识别三次；仍失败冷却该场五分钟，再尝试其他候选。

同一状态目录加进程锁，只允许一个实例运行。同账号在其他机器或浏览器版也应仅运行一个实例；本地锁不提供跨机器协调。重启恢复原目标任务。状态版本 2 的 `done` 表示上次核对时整个选听目标完成。每次正常启动仍要求凭据、认证并读取学校最新记录；仍达标时结束且不重复发送完成邮件，不足则恢复扫描，再次达标时通知。兼容原来的已完成任务重新核对入口：

```bash
uv run --locked main.py --new-task
```

此参数仅允许重新核对已完成目标，不再是普通启动核对学校的前提；待确认或仍在扫描的任务不能重置。若学校记录仍达标则直接结束，不会额外预约或重复发送完成邮件。旧状态版本 1 的单场成功 `done` 首次启动自动转回扫描；待确认活动 ID、冷却和退避时间保持。迁移需要账号，旧客户端不能读取版本 2，不要混用版本或删除状态。状态损坏或账号不匹配时停止，避免覆盖旧任务。
升级前已完成的任务在普通启动时也按当前口径重新核对；若未达标，任务恢复扫描并继续补足。保留原待确认、冷却及退避记录，不通过删除任务或重置来绕过保护。
程序使用私有权限的任务文件、原子替换及持久化写入；任务保存恢复必需的数据和脱敏运行信息，不保存账号密码或完整业务记录。
状态目录内的 `events.log` 保存脱敏事件；邮件失败也会记录，不会改变已确认成功的任务。

## 状态与日志

正常启动预约（含 `--new-task`）、执行 `--check` 或 `--test-mail` 时，会显示一次维护者 `MuZiJin701` 和本项目 GitHub 链接；后台运行时随标准输出写入重定向日志。轮询时不重复显示，`--status` 和 `--help` 不输出署名。正常任务启动和认证成功分别记录 `task_started`、`authentication_succeeded`，终端事件及本地事件带 Unix 时间戳。

正常查询后没有可约讲座，或没有符合筛选条件的讲座，都会安静等待约 10 秒再查询；这不算失败。正常轮询不输出每轮心跳，但会持续更新任务中的运行快照。启动署名不代表登录成功，不应只凭“没有后续输出”判断运行正常。

| 情况或事件 | 含义及处理 |
| --- | --- |
| 正常等待 | 没有合适候选，继续查询；除每日汇报外不发邮件 |
| `event=invalid_activity_data` | 无法确认已有活动的状态、ID 或时间，暂停本轮提交并退避；不是“没抢到讲座” |
| `event=activity_schema_unknown` | 候选关键字段无法识别，暂停本轮提交并退避 |
| `event=attendance_result_pending` | 所选记录已结束但学校未确认打卡或违约，等待学校更新，暂停新增 |
| `event=attendance_category_unknown` / `event=attendance_status_unknown` | 无法确认历史类别或打卡/违约状态，暂停新增 |
| `event=attendance_record_conflict` | 同活动 ID 的记录矛盾，暂停新增，核对学校记录 |
| `event=query_failure` | 连续三轮查询或处理出错；启用邮件时尝试发送一次提醒，正常空列表不会触发 |
| `event=query_recovered` | 已告警的查询／处理完整恢复，尝试通知一次；不等于预约成功 |
| `event=daily_report` | 当天日报尝试，使用最近核对进度并标明时间 |
| `event=preflight_response_unknown` | 预约前检查返回未知结构或未识别失败，暂停本轮提交并退避 |
| `event=mail_configuration_invalid` | 已尝试配置邮件但内容不完整或无效，启动停止；完全不配置邮件允许运行 |
| `event=reservation_unconfirmed` | 已尝试提交但结果不明，核对原活动并等待人工处理，不继续提交其他场次 |
| `event=reservation_succeeded` | 已按活动 ID 查询确认一场预约成功，继续核对目标 |
| `event=goal_completed` | 已打卡至少 8 次且必需三类各至少 1 次，目标完成并结束 |
| `event=task_failed` / `event=unexpected_failure` | 可捕获的异常退出，启用邮件时尝试通知；只读检查只打印诊断、不发邮件 |
| `event=notification_failed reason=...` | 本次通知发送失败，记录固定错误分类，预约结果不受影响，不自动重发 |
| `event=notification_finished` | 本次通知结束，记录通知事件及实际发送耗时，不包含讲座详情 |
| `event=health_write_failed` | 运行快照未能持久化，检查目录权限和磁盘；不能继续相信旧快照的更新时间 |

异常重试一般等待 20、40、80 秒，最多 300 秒；学校要求的更长等待优先。等待截止时间保存在本地，重启后会继续等待剩余时间，期间也可能没有输出。正常查询后才会恢复普通等待节奏，不要通过删除状态文件强行跳过等待。

在另一个 SSH 终端进入项目目录，可以读取状态和最近事件，不启动第二个预约进程：

```bash
uv run --locked main.py --status
tail -n 20 state/events.log
```

日志路径示例使用默认 `state` 目录；修改过 `SEU_STATE_DIR` 时使用对应路径。任务尚无事件时，日志文件可能不存在。日志每行开头是 Unix 时间戳；旧错误会保留，需结合时间判断是否为新错误。

`--status` 不访问学校，首行保持 `status=...`：`not_started` 为尚无任务，`scanning` 为扫描任务，`pending` 为提交结果待确认，`done` 为已打卡目标完成；`legacy_completed` 为旧版单场成功、需要启动新版重新核对。后续字段提供运行信息，解析完整单行输出的旧脚本需改为读取首行或按键解析。

| 字段 | 含义 |
| --- | --- |
| `process_running` | 探测既有任务锁是否被占用，不创建目录或任务，不以旧 PID 判活。锁可用即 `false`，锁占用为 `true`；权限和非法路径错误不会被当作正在运行 |
| `phase` / `last_phase` | 当前阶段；进程不在时 `phase=stopped`，`last_phase` 保留快照中的最后阶段。旧任务无快照或快照无效时为 `unknown` |
| `updated_at` / `snapshot_age_seconds` | 快照更新时间及距今秒数 |
| `last_query_at` / `last_query_age_seconds` | 当前进程最近成功查询时间及距今秒数；`never` / `unknown` 表示还没有成功查询证据 |
| `last_error` / `last_error_at` / `failure_count` | 最近错误码、发生时间及连续失败次数；成功后次数清零，旧错误和时间保留，方便区分历史错误 |
| `next_check_at` | 正常等待或异常退避的下一次检查时间；无计划时为 `never` |
| `activity_count` / `candidate_count` | 最近一次活动列表条数及通过筛选的候选数；不等于预约成功数。只核对待参加预约时为 `unknown` |
| `mail_status` / `last_mail_at` | 当前任务通知状态及最近尝试时间；`disabled` 未配置、`ready` 已配置、`sending` 发送中、`accepted` SMTP 接受、`failed` 失败。关闭邮件不清除上次尝试时间，接受不等于送达 |
| `last_mail_status` / `last_mail_error` | 跨重启保留的最近通知结果及固定错误分类；无错误为 `none`，旧失败无法分类为 `unknown` |
| `last_mail_event` / `last_mail_duration_seconds` | 最近通知事件及实际耗时（秒）；旧记录或未完成尝试耗时为 `unknown`，不是零秒 |
| `selection_updated_at` / `activity_details` | 最近一轮私有逐场筛选快照时间及详情；格式损坏时详情为 `unknown` |

常见阶段：`authentication` 登录中；`my_activities` / `activities` 查询学校；`preflight` / `captcha` / `submitting` / `confirming` 为预约前检查、验证码、提交和确认；`waiting` 为扫描后等待；`waiting_for_attendance` 为计划覆盖后等待打卡；`backoff` 为异常退避；`manual_required` 为需要人工处理；`failed` 为异常退出。

结合 `process_running=true`、阶段和成功查询时间判断进展。`candidate_count=0` 且成功时间约每轮更新，表示该轮没有可选候选，可能尚未开放或被筛选条件排除，不代表提交链路已验证。等待打卡时只核对“我的活动”，成功时间仍更新。最近成功查询只证明当轮所需查询及数据校验通过，不代表预约提交成功。退避可超过 300 秒（学校要求优先），网络或邮件请求也需等待，不能简单把固定时长无更新当成已退出；应结合 `next_check_at` 和进程检查。

进程异常退出或被强制杀死时，最后快照可能仍是运行阶段；任务锁会释放，因此 `process_running=false`，不会因旧快照误报运行。`uv` 启动器及其 Python 子进程属于同一个实例。运行信息不代替外部进程监控，强制退出和断电无法靠进程自身保证邮件通知。

## 服务器后台运行

Ubuntu 24.04 LTS 安装步骤见[README](../README.md#快速开始)，使用同一账号安装与运行。以下后台命令不配置自动重启，进程退出或服务器重启后手动启动。

用户提供的 Linux 终端使用截图，展示后台启动命令和本地状态查询：

![Linux 终端中的 nohup 后台启动及 status=scanning 本地状态查询](images/使用截图.png)

截图中的后台作业号和 PID 仅对应当次启动，不能照抄用于进程检查；`status=scanning` 只表示本地任务状态，不能证明进程仍存活、登录成功或预约成功。截图也不作为长期运行验收证据，进程与日志仍须按下面的方法核对。

完成安装、配置和只读检查后，在项目根目录执行以下命令可在 SSH 断开后继续运行。这些命令会启动真实预约；示例使用默认 `state` 目录，修改过路径时调整相应命令。先检查现有进程，避免重复启动；同一状态目录的锁仍会阻止第二个实例；其他机器或浏览器版同账号实例须由用户自行停止。

```bash
mkdir -p -m 700 state
nohup uv run main.py >> state/runner.log 2>&1 < /dev/null &
echo $! > state/runner.pid
ps -p "$(cat state/runner.pid)" -o pid,comm
tail -n 20 state/runner.log
```

逐行说明：

| 命令 | 作用 |
| --- | --- |
| `mkdir -p -m 700 state` | 创建状态目录，已存在时保留。`700` 表示仅当前用户可读、写和进入；此选项只设置新建目录的权限，不修改已有目录权限。 |
| `nohup uv run main.py >> state/runner.log 2>&1 < /dev/null &` | 启动真实预约，忽略 SSH 断开引起的挂断信号。`>>` 将输出追加到日志，`2>&1` 将错误输出也写入同一日志，`< /dev/null` 关闭交互输入，末尾 `&` 让命令在后台运行并归还终端。 |
| `echo $! > state/runner.pid` | 把刚启动的后台命令的进程号写入 PID 文件，供后续核对；文件存在时覆盖旧进程号，不代表进程启动成功或仍在运行。 |
| `tail -n 20 state/runner.log` | 显示日志最后 20 行后退出；需要持续观察新日志时用 `tail -f state/runner.log`，按 `Ctrl+C` 只停止日志查看。 |

PID 文件记录的是 `uv` 启动器，需结合其 Python 子进程及工作目录核实当前实例，不能仅凭旧 PID 文件判断进程存活。正常完成、人工停止或需交互退出后不会自动重新启动，服务器重启后也不会自启。需要正常预约时保留 `.env` 的私有权限；日志仅保存脱敏事件。

### 查看进程与停止后台任务

在项目目录执行以下只读命令，核对 PID、启动命令和工作目录；路径示例沿用默认 `state` 目录：

```bash
reserve_pid=$(cat state/runner.pid)
ps -p "$reserve_pid" -o pid,ppid,args
readlink "/proc/$reserve_pid/cwd"
```

确认命令为 `uv run main.py` 且工作目录为本项目后，发送停止信号：

```bash
kill -TERM "$reserve_pid"
```

`uv` 会将 SIGTERM 转发给 Python 子进程，见 [uv 信号处理说明](https://docs.astral.sh/uv/concepts/projects/run/#signal-handling)。再次执行上面的 `ps` 命令核对退出；没有对应进程行或 `No such process` 表示该 PID 已结束。PID 文件可能过期或对应的 PID 已被其他进程复用，因此必须先核对。缺少 PID 文件时，不能仅凭这一点认定程序没有运行。

SIGTERM 与 `Ctrl+C` 都走正常停止路径，保存最后运行信息并释放任务锁。停止后保留状态目录，重新执行原启动命令会恢复任务，不取消学校已有预约；预约结果待确认时仍先核对原活动。任务首行仍可能为 `scanning`，但 `process_running=false` 会明确显示进程已退出；核对方法见[状态与日志](#状态与日志)。

后台没有交互终端，遇短信、未知认证挑战或预约结果待确认时，当前程序记录事件、按配置通知并退出，保留任务。确认后台已退出后，通过 SSH 在前台执行 `uv run main.py`，按提示处理；再次停止和后台启动会接着原任务。不能后台自动签到或绕过认证。本次未增加 systemd、容器或新的验证码通道。

## 人工认证

需要短信意味着认证未通过，此时不做业务查询或预约。通过保留的 SSH 交互终端输入 `send` 主动发送/重发短信，再输入六位验证码。
验证码使用与当前学校前端相同的 RSA 加密字段提交；不会后台自动反复发送。错误或过期后可再次主动发送，等待无固定截止时间。
未知认证挑战保持等待并显示固定提示；明确凭据错误或账号受限时停止自动登录尝试。

首版人工输入依赖交互终端；运行时应保留 SSH 终端，或使用已有的终端会话管理工具以便重新连接。
无终端而需要人工输入时会安全退出，保留任务供重新启动恢复；首版尚未提供后台进程的远程验证码输入通道。
Ctrl+C 退出码为 130，不会自动取消已有预约。

## 当前业务数据契约与限制

认证和业务接口来自交接探针；短信发送及加密字段另经学校公开 CAS 前端代码核对。
2026-10-15 已通过新客户端的真实认证与只读检查，完成活动列表、我的活动查询和验证码图片获取；未提交预约。进一步根据真实响应结构与学校 `modules/hdyy/hdyy.js` 核实并适配了“我的活动”的活动 ID、发布状态和起止时间。当时可约活动列表为空，尚未验证候选字段；2026-10-18 非空真实列表暴露了旧解析器使用构造字段、将全部记录静默跳过的问题，现已修正，并让 `--check` 校验同一解析路径。

| 信息 | 当前支持的字段及值 |
| --- | --- |
| 活动 ID | `HD_WID` 或 `WID`，非空字符串 |
| 学校列表标题 / 类别 | `JZMC` / `JZXL_DISPLAY` |
| 学校列表预约时间窗 | `YYKSSJ` / `YYJSSJ`，起止均包含；使用服务器主机时钟比较，需准确校时 |
| 学校列表可预约状态 | `FBZT='1'` 且处于预约时间窗；`FBZT='-1'` 或已有 `YY_WID` 时跳过，未知发布状态报错；另按“我的活动”排除已有预约 |
| 起止时间 | `KSSJ` / `JSSJ`、`HDKSSJ` / `HDJSSJ`，或学校实际使用的 `JZSJ` / `HDJSSJ` |
| 时间格式 | `YYYY-MM-DD HH:MM:SS`、`YYYY-MM-DD HH:MM`、`YYYY/MM/DD/HH:MM:SS`，按 Asia/Shanghai 解释 |
| 学校列表线上线下 / 地点 | 标题开头明确的 `【线上】` / `【线下】` 标记；`JZDD` 为地点字符串，线下提取校区 |
| 兼容的显式字段格式 | `HDMC` / `HDLX_DISPLAY`、`IS_ONLINE` 布尔值、`YYZT='预约'`；主要用于原有构造响应，不要求真实学校响应提供这些字段 |
| 已预约状态 | `YYZT` 为 `已预约`、`预约成功` 或 `取消预约` |
| 非有效预约状态 | `YYZT` 为 `已取消`、`取消成功` 或 `未预约` |
| 学校“我的活动”状态 | 未提供 `YYZT` 时，非空 `HD_WID` 标识预约对应的活动；`FBZT='1'` 为已发布，计入已有预约，`FBZT='-1'` 为活动取消，不计入；未知状态暂停提交 |

已打卡记录仍有预约身份，不能因 `SFDK='1'` 就忽略其时间区间。待确认提交使用 `HD_WID` 核对活动，不能把预约记录自身的 `WID` 当作活动 ID。

学校[前端 hdyy.js](https://ehall.seu.edu.cn/gsapp/sys/yddjzxxtjappseu/modules/hdyy/hdyy.js)的 `queryActivityList` 按 `YY_WID`、`FBZT`、预约时间窗及人数决定按钮，未使用 `SFKSYY` 生成预约按钮。本次真实六条样本的 `SFKSYY` 均为数字 `0`，不能将它解释为开放后仍不允许预约。本客户端不据此开关预约，也不将未提供的 `YYZT` 视为“不可预约”。

当前样本没有独立线上布尔字段，改为仅接受标题开头的明确标记，不按标题任意位置出现“线上”来猜测；缺标记或未知关键字段时报 `activity_schema_unknown`，运行中暂停本轮提交并退避，连续三轮按原通知规则提醒，`--check` 则失败退出。字段校验在判定尚未开放之前进行，避免新格式再次被静默忽略。讲座起止时间损坏仍按 Q11 跳过该候选；已有预约状态、时间或列表完整性未知时阻止提交。

学校页面另外合并 `hdrsList` 人数及 `xsxxList` 预约信息。客户端通过独立“我的活动”查询防重和检查冲突，不把本地候选数当作剩余名额；人数、资格与实时可预约性由 `appiontCheck.do` 及最终提交确认，不能仅凭本地时间窗保证成功。此处没有复制页面的全部展示逻辑，也没有切换到浏览器运行。
当前列表接口支持完整数组；返回分页对象或总数不符时拒绝，不把当前页当作全部已有预约。适配新的实际字段或分页协议前需增加入口回归场景。
未知提交响应按结果待确认处理，仅明确的验证码错误或不可预约响应允许继续其他动作。
