# 可信环境部署：明文 HTTP、无管理台登录与不限制文件权限

2026-10-30 后续改版由 [ADR-0010](0010-configured-admin-login.md) 取代本记录的“无管理员登录”子决策；当前要求管理员认证，HTTP、可信局域网 / VPN 及文件权限取舍仍保留。以下描述原决策，不代表当前匿名访问能力。

2026-10-30 需求澄清，用户确认管理台只在本人或少数可信操作者、可信局域网或 VPN 的环境中使用，并据此确定三项同源决策：管理台使用明文 HTTP 而非 HTTPS；不提供管理员登录；不限制部署环境的文件权限。三项都服从“使用范围可控、以简化部署为先”的前提，因此合并记录，不再分别维护证书、登录和权限约束。

管理台默认监听 `0.0.0.0:8080`（`SEU_WEB_HOST`／`SEU_WEB_PORT`），可用 `--config` 指定 `.env`；删除 `SEU_WEB_CERT`／`SEU_WEB_KEY` 以及证书准备、续期、反向代理和 HTTPS 往返等全部内容。删除 `SEU_WEB_ADMIN`、`SEU_WEB_PASSWORD_HASH`、`--hash-password`、登录页、会话 Cookie、CSRF token 与登录限速，管理台不再区分操作者身份。访问学校系统的客户端请求不受影响，仍使用通过证书校验的 HTTPS。

不再要求 chmod、UMask、`0600`／`0700` 等文件权限设置，systemd 示例去掉 `UMask` 与权限步骤；`.env`、数据目录和日志仍不得提交、上传或公开，但不再把文件权限当作安全边界。本决策取代 [ADR-0007](0007-direct-https-without-reverse-proxy.md)，并修正 [ADR-0005](0005-local-plaintext-school-credentials.md) 的文件权限边界；后者“凭据不得进入仓库、日志或网页响应”的要求继续有效。

残留风险须如实保留：同网段任何可达机器都能读取和操作管理台，也能接触明文保存的学校账号密码；没有 TLS，局域网内的窃听与篡改无法被本程序发现；学校账号密码、短信验证码和讲座数据因此扩大暴露面。程序不承诺这些风险可被配置消除，只以“仅少数人和机器使用”为前提。

决策可逆：以后若需要跨网段访问、多人协作或更强边界，可重新引入 TLS 与管理台登录，并恢复文件权限约束；届时以新的 ADR 取代本决策。部署与操作见 [Web 指南](../web.md)，完整需求见[多账号与 Web 改造](../requirements.md#多账号与-web-改造)。
