# Domain Docs

本项目采用 single-context。

## 阅读入口

- 探索业务代码或讨论领域概念前，读取根目录 [GLOSSARY.md](../../GLOSSARY.md)。
- 探索或修改某个领域行为前，读取 `docs/adr/` 中与该行为有关的 ADR。
- 文件或目录尚不存在时直接继续；术语确定或真实架构取舍发生时再创建。

## 布局与旧文件迁移

- 统一使用根目录 `GLOSSARY.md` 和 `docs/adr/`；本项目采用 single-context，不拆分领域地图。
- 发现旧 `CONTEXT.md` 或 `CONTEXT-MAP.md` 时，先提示分别迁移为 `GLOSSARY.md` 或 `GLOSSARY-MAP.md`，再在已授权范围内用 `git mv` 保留历史，并同步本文、根目录技能入口及其他引用。
- 目标文件已存在时先核对双方内容并确定合并方案，保留现有术语和用户修改；布局仍按 single-context，旧地图的保留方式需在迁移方案中说明。

## 写作规则

- Issue、规格、代码及测试中命名领域概念时，使用术语表的统一词汇。
- `GLOSSARY.md` 仅记录领域定义；接口、认证协议和实现细节放在相应技术文档中。
- 缺少必要术语时，先明确含义，再更新术语表。
- 方案与现有 ADR 冲突时，明确指出冲突及重新决策的理由。
- 仅为难以逆转、缺少背景会令人困惑且经过真实取舍的决定创建 ADR，
  路径为 `docs/adr/NNNN-简短名称.md`。
