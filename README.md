# 东南大学素养讲座预约控制台

[各时期线程协作与预约查询策略（图表）](docs/thread-query-strategy.md)

[English](README.en.md)

支持多学校账号的讲座预约工具，提供中文管理台和原有 CLI。管理台使用明文 HTTP、需要管理员账号和密码登录，只部署在可信局域网或 VPN；多个管理员共同管理同一套学校账号；每个学校账号独立运行、认证、核对预约结果和统计选听进度。访问学校系统的请求仍使用通过证书校验的 HTTPS。

目标仍为实际选听 **8 场人文与科学素养系列讲座，法律、艺术、心理健康各至少 1 场**。沙龙可按配置预约但不计入目标；测试活动与购票公告不预约。最终认定以学校为准。

所有阶段保留主线程、活动列表只读线程、历史列表只读线程和可选邮件线程，预约验证码预取、现场及判错重取统一使用一个按需工作线程。列表目标请求开始间隔：普通期随机 4–6 秒；预约开放前 5 秒至后 9 秒随机 0.05–0.10 秒；其余开抢时段（前 30 秒至后 5 分钟）随机 0.5–1.5 秒。历史普通期约每 25 秒刷新、快照有效期 30 秒，开抢期约每 5 秒刷新、有效期 10 秒；普通期出现可提交候选时请求历史线程重新核对。目标间隔包含请求耗时；没有待抢目标且无待确认提交时提前降频，线程继续运行。随机化不保证避免自动化识别。详见[查询策略](docs/usage.md#开抢与拥塞恢复)。

普通期手动取消、考勤与新增预约可能延后约 30 秒加一轮扫描及请求耗时反映；以预约清单同步时间判断新鲜度。新策略须更新代码并重启原 CLI 或管理服务才生效。

两条只读线程自行查询与重试，普通期请求预算 10 秒、开抢期 2 秒；主线程采用版本通知及绝对等待截止时间，消费快照、认证、派发验证码任务和串行提交，不再同步兜底查询。验证码线程归还主会话后才能认证或提交，提交前用已有可靠快照复核候选及冲突，空闲不取图；任务状态仍只由主线程同步写入，邮件独立排队发送。私有日志复用安全文件句柄，服务器磁盘实测未触发增加写线程的条件。当前实现、离线与真实只读检查见[统一验证码线程验收](docs/acceptance/2026-11-04-captcha-worker.md)与此前 [P0/P1/P2 验收](docs/acceptance/2026-11-04-event-preparation.md)；真实开抢仍待验收，生产服务未更新。历史结果见[统一线程验收](docs/acceptance/2026-11-03-unified-workers.md)与[19:00 实战记录](docs/acceptance/2026-11-03-opening-recovery.md)。

快抢、慢抢列表快照均允许保留成功响应后两秒，明确查询失败仍暂停新增；见[调整验收](docs/acceptance/2026-11-04-opening-snapshot-2s.md)。

## 安装

生产部署使用 Linux、Python 3.12 和 uv；Windows 可运行 CLI 和离线检查。已有工具可直接使用。

```bash
git clone https://github.com/MuZiJin701/seu-lecture-reserve-http.git
cd seu-lecture-reserve-http
uv sync --locked
cp -n .env.example .env
```

已有配置保留原文件，按 [.env.example](.env.example) 补充 Web 字段。程序自动读取当前目录 `.env`，不要 `source .env`；进程环境变量优先。

## 配置并启动管理台

直接在 `.env` 的管理员列表填写账号和密码，无需生成哈希。没有有效管理员时服务拒绝启动；可添加多个同等权限管理员，增删或改密后重启管理服务生效。配置示例（替换示例密码）：

```dotenv
SEU_WEB_HOST=0.0.0.0
SEU_WEB_PORT=8080
SEU_DATA_DIR=state
SEU_WEB_ADMINS='{"admin":"换成你的密码","other":"另一个密码"}'
```

已有密码哈希仍兼容，`uv run --locked seu-reserve-web --hash-password` 仅为可选工具。直接填写的密码在启动时派生为内存中的哈希，不改写配置；`.env` 仍含明文密码，不要提交或分享。

可用 `--config /绝对路径/.env` 指定其他配置文件。`SEU_WEB_HOST=0.0.0.0` 只是让服务监听所有网卡，**不是浏览器访问地址**；本机请打开 `http://127.0.0.1:8080`，其他机器用服务器实际 IP。管理台仍使用 HTTP，不需要 TLS 证书，只应部署在可信局域网或 VPN；登录信息和会话没有传输加密，不要把端口暴露到公网。管理员会话固定有效 12 小时，退出不停止预约，服务重启后需要重新登录。

```bash
uv run --locked seu-reserve-web
```

打开 `http://127.0.0.1:8080`（服务器部署换成实际地址）。登录后，在卡片队列末尾新增学校账号；选中卡片，在详情区修改配置、查看进度与当前预约，保存后手动点击“启动预约”。多人编辑发生冲突时拒绝覆盖并保留输入。需要短信时，在对应账号卡片里发送短信并输入验证码；其他账号继续运行。关闭网页不会停止后台任务。

运行中的管理台账号保存配置时会安全停止并重启。若外部 CLI 已持有该账号状态锁，保存会被拒绝；若 CLI 在保存完成后抢先取得锁，保存仍成功，页面显示“CLI 正在运行”，CLI 使用保存后的配置。

[完整 Web 使用、systemd 部署与风险说明](docs/web.md)。新部署从空数据根目录开始，不检测也不导入旧的单账号任务文件。

## 邮件与账号数据

SMTP 发信账号仍在服务器 `.env` 中配置，例如 `SMTP_USERNAME`、`SMTP_PASSWORD`；每学校账号在网页指定一个收信邮箱。留空关闭该账号邮件，绝不默认发给公共发信邮箱。启用邮件而公共配置无效时阻止该账号启动；发送失败不改变预约结果。填写邮箱后自动发送重大告警及每次成功通知，可在网页发送测试邮件。

学校密码和 Cookie 按已确认方案**本地明文保存**，仅服务器使用，网页不回显密码；数据目录与 `.env` 不进入仓库。明文保存且不限制文件权限，能访问数据目录的人即可取得凭据。删除账号前先停止，存在待确认或时间占位时先核对；删除本地数据不会取消学校已有预约。

每学校账号使用独立进程，Web 内同账号只允许一个工作进程。账号身份锁已移除，同一学校账号允许并发登录（单账号单机约 4 分钟只读实测，见[并发登录记录](docs/acceptance/2026-10-30-concurrent-login.md)）；开抢期仍建议避免额外的诊断登录。10 账号仅为验收目标，不设硬上限；实际容量取决于设备。不同数据根目录的两套任务无法互相发现，也不能互相协调。日常预约建议同一学校账号只保留一套实际运行任务，由操作者协调，避免重复流量。

## 保留的 CLI

```bash
# 已纳管账号使用其统一状态；账号参数可为一卡通号或内部 ID。
uv run --locked main.py --account 你的一卡通号 --status
uv run --locked main.py --account 你的一卡通号 --check
uv run --locked main.py --account 你的一卡通号
```

已纳管账号统一开启设备信任、预热、验证码预取、后台历史刷新、开抢对齐和成功通知，不再按标题过滤；网页隐藏这些选项。当前预约清单复用引擎已有查询，显示最近同步时间，待确认和时间占位单独列出。

不带 `--account` 的旧单账号 `.env` 运行方式和原配置能力仍保留，可用 `uv run --locked main.py` 启动。已纳管账号使用 `--account`。入口、恢复和诊断字段见[CLI 使用指南](docs/usage.md)。
